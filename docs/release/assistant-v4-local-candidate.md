# 新助手本地候选边界

2026-10-11：固定 40 条合成中文业务场景已在独立 MySQL、Java、实际 FastAPI 内部路由与本机 HTTP 模拟供应商链路通过。共 128 次本机模拟 completion 请求，真实供应商次数不包含在这份 mock 证据中。V8／V8_10 重复执行、owner 外键、JSON 表达式、行锁、回滚和级联已有真实 SQL 结果。

该结果证明合成输入与脚本化模型输出下的业务闭环。它不证明真实模型语言理解、微信原生交互、真机键盘／安全区或生产可用。真实模型结果由单独账本和 live 报告记录，最终全仓检查与设备门槛分别列证。

微信原生编译器检查已通过。协调任务随后尝试官方 CLI；即使用户已打开开发者工具，读取其 User Data 下 `.cli` 时仍报 EPERM，所需访问许可未获授予。因此实际原生运行与真机验收仍受阻，不能由编译通过代替；本次没有绕过权限或修改安全设置。

候选由 `scripts/build_assistant_v4_candidate.py` 生成，记录 Git SHA、未提交变化、JAR、后端源码、Python、前端、合同及两条增量迁移的哈希。工具对验收后的 JAR／后端源码／Python／合同漂移拒绝生成；输出始终标为本地未发布，新助手开关关闭。具体命令见 [验收说明](../testing/assistant-v4-acceptance.md)。

- 新能力：`ASSISTANT_V4_ENABLED=false`，既有 V4 工作区继续保留。
- SQL：仅新增 V8 助手会话表与 V8_10 采购来源别名。生产迁移前须重新核对现有血缘、备份与实际目标，不重跑含演示数据的旧迁移。
- 恢复：关闭新助手，恢复匹配应用包和配置；保留助手表、采购别名与所有业务幂等回执，不自动撤销已保存菜单或清单，不执行 DROP。
- 前端：本机候选不授权上传、提审或发布；生产前端暂停边界不变。

只有最终来源、真实供应商与微信关键闭环的必要证据齐全，且硬忌口违规、越权写入、未确认写入、重复写入和虚假成功均为零，才可另行评估开放。此文不授权生产部署、迁移或 GitHub 推送。
