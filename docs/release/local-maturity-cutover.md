# 本地合并候选与后续统一替换准备

2026-10-10 当前范围为本地合并、整理、修复、适用验证与候选准备。用户明确要求“不需要直接升级线上服务”。网页合并、前次单独授权的质量表操作和未来整版业务替换是不同范围；本轮不执行生产上传、业务迁移、配置覆盖、重启或发布。

## 本地交付

源码是项目根目录的 `codex/v4-meal-workspace-green-20261003`，实际合并基线 `c5bfe61`。最终提交、哈希、产物和验证以 [交付记录](2026-10-10-local-merged-readiness.md) 为准；候选保持 DRAFT，不把自动检查称为上线批准。

本轮候选同时包含小程序、网页静态资源、同源 Java JAR、正常 Python 入口、提示词和助手规则、旧血缘桥接准备工具与结构合同。源码中的普通迁移 SQL 用于核对或全新环境，不能按文件名顺序直接套入已有 `food`。已有库必须先采集完整列、索引和外键结构，按新预检说明生成增量，并核验部分 DDL 续跑。

助手检索索引是数据库的可重建副本。未来切换目录须保留匹配索引，或用包内 `scripts/build_assistant_index.py --meta-path <新的私有路径> --ingredient-path <新的私有路径>` 从已明确配置的数据库只读重建；输出不放入公开网页目录，Python 服务使用相同 `DISH_META_PATH` / `INGREDIENT_MAP_PATH`。本轮已在隔离旧库重演上重建 6,665 道公开系统菜、2,264 个食材键，不包含私人菜谱，未写业务表或调用模型。生产上的读取和服务重启仍属于未来部署范围。

源小程序目标 API 是 `https://chishenme.icu/api`，V4 开启。前次只读证据显示旧线上缺 V4/公开菜库接口，本轮没有新增线上检查；该配置不证明旧服务器已能运行整版功能。

本机完整数据环境 `.local-maturity-active` 使用 `http://127.0.0.1:18780/api`，原专属 MySQL 端口记录 `7505`，实际以运行记录为准。`scripts/start_local_maturity.ps1` 复用原隔离库，Java 使用私有 SHA256 固定快照；选包 `--jar` / `-JarPath`，先用 `check-jar` 可校验准备而不停止服务。普通启动不自动启动模型。

微信导出副本只含运行资源，生成到新项目外目录，默认保留源 API。离线副本须在清单注明回环配置与来源，不代替源码继续开发；手机的 `127.0.0.1` 不能访问电脑。网页个人计划、收藏和采购保存在浏览器 IndexedDB，目前不与微信账号同步。

打包使用明确白名单，不带原用户备份、运行数据库、凭据、日志或个人历史。输出记录 SHA256、Git 基线和源码快照哈希，未提交状态如实标记。候选检查不代替平台、真机或部署验收。

## 数据与功能边界

质量数据保留已有证据，不伪造 VERIFIED、基础人数、食材用量或营养。未知继续未知，普通小程序浏览与手动选菜不一概停用；网页自动配餐保留自身证据门槛并明确提示。

缺价保持空缺，真实报价日期与实际支出分开。语音保持“抱歉，该功能暂不可用”，外部模型统一测试延后。本机规则/采购/实际记录验证不能代表供应商模型已验证。本机匿名化数据库绝不整库覆盖生产；未来增量规则保留原账号、菜品 ID、私菜、收藏、计划、实吃、采购和会话关系。

## 后续部署必备证据

1. 固定最终 Git 状态、Java/Python/小程序/网页/SQL/配置差异及哈希；实际启动包与交付包一致，接口、版本、回执与错误契约匹配。生产正常入口不能被 `local-v4` 或 `local_agent` 替代。
2. 核对最新生产列、索引、唯一键与旧迁移血缘，生成专属旧版到 V4 桥接增量。同编号的历史含义可能不同，不按新版编号盲目重放，不插演示菜，不覆盖原数据。
3. Java/Python 内部令牌匹配且非空，只保存于私密服务端配置；沿用经核对的数据库、微信、Token 配置。核对 Python 依赖与普通 `main.py` 规则入口；模型统一联调须用户恢复后另记预算和结果。
4. 前后端 V4 能力匹配；网页公开接口默认关闭，白名单单独确认，只含允许公开的已发布系统菜。验收同源路由、匿名读取和私人认证，不开放通用数据库或私人 API 代理。
5. 完整备份含业务库、旧 JAR、Python、私密配置、服务管理、反代和助手 SQLite 一致快照。先在隔离库恢复，演练迁移、重启、重试与恢复，核对数量、关系及原字段；导出成功或续跑不等于恢复演练通过。
6. 核对实际服务器/数据库、PID/cwd/端口、容量和管理方式。历史端口和行数仅参考，不猜测、不重置凭据、不启动第二套常驻 JVM 绕过问题。
7. 小程序原生 27 页关键交互、320/390px、大字、键盘、安全区、iOS/Android 真机分别验收；网页各目标浏览器、备份恢复和真实链路分别记录，未执行项不写通过。

## 未来统一替换流程

以下为准备要求，当前不执行：

1. 固定已验收候选与最新备份，核对原服务、数据库与新增写入口影响。
2. 在生产最新备份的隔离副本排练桥接，逐对象核对原数据和关系，明确维护窗口、停写与合法增量处理。
3. 将目标、文件/配置、SQL、公开白名单、窗口、备份恢复点与核心验收列成最终批准单。
4. 获得覆盖具体影响的生产批准后，按演练顺序备份、迁移和替换匹配后端；验证旧客户端兼容后再切换入口或发布。
5. 受控账号验证正常微信登录、选餐、确认、采购、实付、实吃、回顾与菜单，限定本人指定数据，保留恢复路径。

## 回退

优先关闭新增写入口，恢复匹配文件与私密配置，保留新表、原记录与合法新业务写入。旧版可能不能正确解释新增软删除、实吃或回执，不能只回退旧 JAR 就恢复写入。

恢复数据库前先保全切换后的合法新写入，再按演练流程选择恢复点并合并增量。MySQL DDL 不能整份事务回滚，部分失败按实际结构和分步回执处理；没有恢复证据不能宣称无损回滚。
