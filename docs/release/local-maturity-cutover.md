# 本地成熟化候选与线上统一替换

当前状态为 DRAFT，仅用于本地体验、评审和后续发布准备。线上业务没有迁移、覆盖或重启。

## 本地交付

启动入口：`scripts/start_local_maturity.ps1`。API 为 `http://127.0.0.1:18780/api`，V4 开启，真实语音与外部模型联调暂停。关闭终端前先结束体验；重新运行同一启动器保留数据库数据。

微信预览由 `scripts/export_local_miniprogram.py --out <新目录>` 生成，只含前端运行资源。源项目仍是唯一开发来源；修改后重新导出到新目录，不在导出副本继续开发。开发者工具必须连接本机服务；手机真机无法直接使用手机自己的 127.0.0.1。

候选打包器使用明确的文件清单，不带原用户备份、运行数据库、凭据、日志或真实用户历史。每个输出文件有 SHA-256，Git 基线与源码快照哈希分别记录；未提交快照不能冒充已提交版本。

## 发布前必备证据

1. 人工来源核验、用量与基础份数核验、首批实做及图片授权；当前 VERIFIED 为 0，不能发布成“可信配方已覆盖”。
2. 原生 27 页逐页交互、320/390px、大字、键盘与安全区、iOS/Android 真机；编译不代替交互。
3. 外部模型统一测试由用户恢复后执行，覆盖拒绝项改口、锁定私菜、他人账号、无候选、超时、跨日与部分写入恢复；记录请求预算。
4. 隔离环境完整备份与恢复式回滚演练、重启保持记录、旧客户端兼容与异常恢复；本轮中断续跑并不等于回滚通过。
5. 只读核对最新线上版本、Schema、运行端口、配置入口和数据规模，重新取得最新备份。2026-10-08 数据只作为开发基线。

## 统一替换步骤

1. 固定最终 Git 提交、JAR/前端/Python 源/质量包/迁移包哈希及检查证据；关闭生产自动迁移。
2. 以线上最新备份在隔离库排练增量迁移，逐对象核对用户、私菜、收藏、菜单、计划、实吃、回执和采购关联；明确停写窗口与增量处理。
3. 将具体目标服务器、数据库、操作、预计窗口、备份位置、回滚版本和核心验收列成最终审批单，再请求生产变更批准。
4. 批准后先备份与核验恢复点，再按已演练顺序变更数据库和后端；检查兼容旧客户端后才切换小程序 API/发布版本。
5. 用受控账号验证登录、选餐、确认、采购、实吃、回顾与菜单；核对真实错误和延迟，满足门禁后结束停写。

严禁把本地匿名化数据库整体覆盖线上数据库。本地库只能证明迁移与产品行为，线上须在最新业务数据上应用已审阅的增量规则。

## 回退

优先回退前端入口与兼容 V3/V4 的后端，不删除新增表或历史快照。需要恢复数据库时，先保全切换后的新写入，再按已演练的备份恢复与增量合并流程执行；未经恢复演练不能宣称可无损回滚。
