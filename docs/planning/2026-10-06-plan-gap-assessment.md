## 本次查到的具体收尾点

1. **高级/历史入口不是历史视图完成的证据。** [chat.js](../../pages/chat/chat.js) 在 V4 开启时选择共享工作区行为，[chat.wxml](../../pages/chat/chat.wxml) 显示同一模板；[共享行为](../../utils/meal-workspace-page.js) 的高级按钮仍导航到该路由。旧草稿可导入、会话 API 可用，不等于用户能浏览完整历史；也需避免助手页再进入自身形成重复页面堆叠。本项依据源码，不是本次原生复现。
2. **采购费用详情挤在待买勾选之前。** [购物模板](../../pages/shopping-list/shopping-list.wxml) 先渲染包含全部 `pricingRows` 的费用卡，再渲染食材清单；同一食材会在费用区与采购区分别展示。建议首屏保留费用总览，逐项实付靠近食材，详细参考价/来源折叠，保留既有金额与数量契约。实际屏幕影响仍需原生核验。
3. **当前餐到实际记录还有操作负担。** 日历已有“按计划吃了/记录实际/取消安排/撤销”，回顾能回到原记录；当前餐和做饭页主要跳到整日详情。需明确目标餐次、提供复用现有接口的快捷记录，不能新建第二套已吃标志。
4. **发布与版本尚未形成完整候选包。** `project.config.json` 仍为 `trial`，前端源码直接指向本机；当前工作区未形成包含功能的最终提交。下一步应准备可复核版本、稳定基础库和环境选择，而不是把本机开关打开等同上线。
5. **规划索引过时。** 原索引仍说“新增功能等待授权”，原总方案仍有“第一道菜/曝光反馈/v3.2.0”的基线描述。它们是历史快照，不应继续充当当前状态；本次发布 v2 总方案并保留 v1。
6. **热量能力文案尚未一致。** 根 [README](../../README.md) 的统计和版本描述仍有“智能估算总热量和日均热量摄入”，实际回顾明确不把类别次数当营养。应保留真实历史版本说明，但不能让旧功能宣传冒充已验证的当前营养能力；列入 B0/T04 收尾。
