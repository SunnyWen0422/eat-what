# 后续开发总方案 v2

日期：2026-10-06。当前开发分支：`codex/v4-local-integration-20261006`；Git 基线 `c152550`，主体实现仍包含本地未提交与未跟踪文件。v2 以实际首批成果为起点，替代 v1 中已过时的“全待开发”描述。[完成度复核](2026-10-06-plan-gap-assessment.md)是本方案的状态依据。

本次仅制定方案、更新文档，不执行下面的开发、派工、模型调用、自动化、发布或数据库转换。两份用户原文保留在 `sources/`，其中 Dot 职责是建议内容，不表示已经启用。

## 产品目标与边界

先让用户独立完成一餐，再让 Agent 帮用户跨模块完成同一套业务操作。今天、菜谱、计划、我的四 Tab 保留；收藏、自定义、清单、回顾/报告和偏好拥有稳定独立入口。模型不可用时，页面基本操作继续可用。

固定契约：草稿≠正式计划，计划≠实际，已买/做饭结束≠已吃；修改计划不修改历史实际；临时要求不自动成为长期偏好；未知量/价格/营养不是 0；Java/MySQL 权威写入；模型只能读取授权数据、提出结构化动作，不直接写业务库。业务日期为 `Asia/Shanghai`，人数保留 1–50、首次默认 2、手动菜数不随人数重置。

继续非商业路线，不增加自营订单、支付、配送。语音按用户决定冻结，只保留不可用弹窗；T17 参考价与实付继续保留，缺价不猜、真实报价日期可追溯、当前食材实付记一次，不分摊或自动勾选。

## B0：把当前成果变成可复查版本

核对规范仓库 `project/`、分支、工作区差异和未跟踪文件；保留归档。建立本地候选版本与文件指纹，将业务源码、生成来源和测试一并纳入，私有配置/数据库/日志不进入源码包。是否提交由后续具体开发任务范围决定，推送、PR、合并另按授权执行。

纠正文档的阶段、路由数和版本事实：原生矩阵 26 页/15 组件，本机 V4 开启，真实语音冻结。根 README 的热量/日均摄入宣传应与当前真实能力一致，历史稳定版与本机开发版分开说明。原实施计划复选项按证据关闭；原生、旧库桥接、固定模型评测仍开放。

开发/测试/发布地址与开关要可显式选择，发布检查拒绝 localhost 和 `trial`。发布入口不能加载本机免微信登录 Profile，也不能包含 `.local-v4`、私有 YAML 或模型凭据。稳定基础库选择在实际有原生证据时确定，不现在猜版本号。

## B1：先补齐现有单餐体验

1. **高级/历史视图**：保留原深链接与当前餐身份；从当前餐进入后能看本用户历史、旧草稿，选择导入时重新读取版本；只浏览不创建第二份业务草稿，返回恢复原菜单。助手页不再重复导航自身。跨模块统一助手以后在 B4 扩展。
2. **采购首屏**：待买食材的勾选和数量为主；顶部费用总览，逐项实付靠近对应食材，参考价及来源按需展开。保留 0 金额、缺价、部分已购、混合单位、原数量警告和未知请求原 payload。计划变更采购采用用户审阅的差异预览，不静默重写已买/手工项。
3. **实际记录**：在当前餐或做饭结束后提供“按计划吃了/实际有变化/没按计划做”，复用 `MealConsumptionService`；明确未记录、跳过、外食和实际修改。跳转携带准确餐次。更改/撤销同餐不增加计数，不能自动推断个人摄入。
4. **轻量进度**：是否增加“食材已核对/做饭结束”辅助状态在本批设计中确定；只作导航帮助，不替代计划和实际。计时器、常亮、并行烹调先不插入首版。
5. **原生验证**：每页记录版本、基础库、设备/系统、步骤、预期/实际、截图/问题。覆盖大字、320 宽、长菜名/步骤、键盘、前后台、空态、错误、账号退出、冲突。关键路径真机与双设备单列。编译、页面打开和截图不能替代功能验收。

费用/购物/实际的页面操作继续独立可达；不要求用户必须采购后才能做饭。

## B2：模型、事务、恢复与迁移

建立十类固定任务：否定/改口、临时/长期、日期切换、局部替换/锁、强限制无解、无来源 ID、缺失数量/时间、超时/坏 JSON、并发候选、资料指令注入。建议先做 60 条本地样本，M2 增加至少 30 条复合样本；数量是组织规模，不是质量保证。

样本先离线校验，不消耗模型。真实运行记录模型/端点标识、参数、提示词 hash、数据版本、caseId、目标/限制/读写断言、结果、调用数、耗时和费用。安全违规、错误对象和越权写入必须为零；可满足任务成功率单列，具体质量目标依据首轮基线确定，不靠全部拒绝通过。当前 14 秒/四轮是执行预算，不能写成实测 P95。

当前授权总上限仍是 20 次，已用 12 次；余量不足完整评测。预算外真实请求等后续明确授权，本方案不重置计数或擅自增加额度。

资源分工按实际条件确定：开发执行者负责代码、隔离数据与自动/服务端验证；持有设备的人负责真机复现与体验反馈；数据来源/许可与方法由有相应资料和审阅条件的人核对；用户决定范围、模型预算及发布。环境缺口是待办，不伪造验收，也不自动建立 Dot 或新聊天派工。

服务端演练覆盖同 key 重放/改 payload、服务已提交但客户端超时、双连接冲突、取消晚到结果、JVM 中断/租约恢复、确认时配方改变，以及价格实付来源删除/版本冲突。每个动作保持单领域事务，模型请求不放进数据库事务。

A01 先扩展离线结构审计到列、索引、迁移记录和对象数量，建立 fresh/V4/legacy/mixed/checksum 异常样本。旧血缘只在明确的隔离副本上设计和演练转换；不能把新库 V1–V5 成功等同旧库可升级。未提供安全副本或脱敏导出时保留设计，不连接生产。

## B3：可信数据与价格来源

对授权离线基准全量剖析字段、缺失、重复、异常；再按高频、早餐、来源、质量分层人工复核。200–300 道只是试点候选规模，不能报告成已审校。审核内容包括来源/图片许可、基础份数、食材量/单位、别名、规格/状态、做法、可信用时和标签。

保留原件，输出新数据、可重跑脚本、审计报告和待核对清单。模型推断保留来源与待审核标记；不因索引重建改变归属/发布状态。

价格独立验证真实官方附件的零售列、真实报价日期、单位、规格、映射及过期边界；批发列、公式异常或布局未知不能自动接受。无已核实批次就空缺；自动采集是否启用依据来源实际可用性另行决定。第三方采购入口只有真实配置和设备验证后开放。

## B4：跨模块 Agent 工具层

先审计现有服务契约，复用其数据，不造 Agent 专用收藏/计划/清单表。分两轮交付：

| 领域 | 读取与动作 | 接入前补齐 |
|---|---|---|
| 菜谱/个人菜 | 授权搜索、详情、个人副本创建/编辑 | 可见性、来源快照、创建幂等及编辑版本 |
| 收藏 | 查询、设为已收藏/未收藏 | 目标状态语义，重复执行不翻转、不因重复键报假失败 |
| 当前餐/计划 | 读最新工作区、保存/复制/调整指定餐 | 复用工作区/计划独立版本；覆盖已有对象审阅差异 |
| 清单/实付 | 读当前清单、加/改/核对食材 | 版本、来源、数量信任与金额范围；买过不等于吃过 |
| 实际/回顾 | 读指定周期、明确实际保存/撤销 | 计划/实际分开，记录覆盖与证据引用 |
| 偏好 | 读/改用户明确指定字段 | 当前餐与长期范围、最新值、并发保护 |

第一轮只读能跨模块查最新状态；第二轮从目标唯一的收藏和个人副本等可逆动作开始，再接计划/清单/实际。认证主体来自 Java，拒绝模型提供的 userId；写提案包含目标、预期版本和 payload hash，服务端决定确认策略。

用户明确要求、唯一目标的低风险操作可直接执行；覆盖计划、删除、批量或歧义动作展示差异或最小必要确认。模型不可用时原页面继续工作。行为推断只作可撤销的软排序信号，保留来源/置信度/失效时间，不变永久禁忌。

## B5：复合任务与稳定报告

扩展现有任务底座，步骤至少有 `stepId/intent/target/dependencies/operationKind/confirmationPolicy/expectedVersions/requestId/payloadHash/status/resultRef/error`。步骤 ID 与幂等键由服务端分配并持久化；编排表保存执行状态和业务引用，不复制业务数据。

无依赖项可以独立执行，有依赖项等真实回执。状态区分成功、失败、未知、等待输入/确认和取消。超时先查回执再以原键重试；只重试失败/未知项。取消阻止未开始步骤，已成功动作不偷偷撤回。

首个报告是有覆盖度的行为回顾。报告包含用户、日期范围、`basis=plan|actual`、源对象/版本、方法版本、覆盖、缺失、结构化结果和稳定 ID；统计/报告页可独立再次打开。源记录变化后标注旧报告过期，重新计算生成新版本；不静默改写原报告。

必须打通原文三组任务：

1. 保存今日晚餐后分析最近一周：先区分计划/实际，营养数据不足就说明缺口并提供可证实回顾，不把刚保存的计划算作摄入。
2. 收藏菜品并创建个人副本：解析唯一对象，不修改公共菜；部分失败只恢复失败项，页面立即读取同一对象。
3. 分析实际晚餐重复并调整明晚：建议附证据；仅分析不写计划；用户明确要求调整才执行，已有明晚计划仍审阅差异。

## B6/B7/B8：有依赖地扩展

**多餐**首版限用户指定三天晚餐，不自动延伸整月。保留/跳过/逐餐或分组确认，未确认草稿可续作；跨餐采购显示差异，重复恢复不重复添加，实际历史独立。价格/库存不可靠时不作硬优化条件。

**营养**先定标准食材 ID、别名、规格、生熟/可食口径、授权来源/条目/版本、原配方量和基础份数；确定性服务生成快照，模型只解释。先整道菜/整餐覆盖，再在用户确认份量后扩个人口径；油盐、未知量或部分缺失明示，未知不填 0。发布前完成人工计算金标准、容差和方法专业审阅。

**家庭/库存/第三方**先有使用需求再做。家庭邀请/退出和成员作用域必须独立，人数不等于账号授权；没有可靠消耗记录不显示精确库存余额。第三方优先复制/分享/搜索跳转，不自建交易系统。Dot 可作为未来协调工具，未启用，权限和预算以实际授权为准。

## 验收、指标与交付

发布阻断：跨用户数据、错误日期/对象、重复业务写入、静默放宽硬约束、数据损失、不可恢复迁移、关键原生路径失败。非关键问题记录实际影响和处理决定。

每批交付包含用户问题、候选版本/文件、业务差异、自动/数据库/模型/原生各层证据、未执行项、成本/隐私影响和关闭/恢复方法。日志按 task/request ID 关联状态、时延、错误码和版本，不记录密钥、录音或完整自由文本。数据留存/删除按对象区分，旧聊天、步骤回执与实际历史不能一律套同期限。

产品指标先追踪有效曝光→确认、局部调整后采纳、明确实际记录覆盖、未知请求恢复、跨模块一致性、完成一餐的模型消耗。计划、实际、采购分开计量；同账号/日期/餐次去重，修改不新增，撤销影响对应统计。小范围可用性观察先验证找入口和完成任务的负担，不宣称统计显著增长。

发布另成具体任务：稳定基础库→原生/模型/数据与恢复门槛→候选包/差异/回滚→用户批准→兼容后端与受控开关→小范围观察。生产连接、迁移、推送/合并和发布不由本方案自动触发，不虚设上线日期。
