# 助手表达与执行衔接

用户已批准本次产品调整。本计划在当前正式分支本地实施，不发布、不访问生产、不新增真实模型请求。

1. 增加协商协议 meal_reply.v2。卡片展示名由模型生成，真实菜品 ID、详情、图片、业务数据仍来自授权查询。展示名不写回菜谱库；旧协议保持兼容。
2. 新客户端协商 direct_execution_v1。模型依据明确指令提出动作，服务端继续校验归属、版本、依赖和幂等，通过原有绑定任务执行保存/采购，无二次确认。历史预览不自动执行；歧义由模型询问必要信息。
3. 新协议不再调用后端原话关键词解析器推断临时条件；模型使用结构化条件。不可执行条件仍不能冒充已应用。
4. 处理中支持追加指令。先持久保留补充内容，取消并核对旧任务，再带最新工作区继续。取消失败/结果未知时保留补充，不并行写入；已完成动作不能重复执行。
5. 仅执行相关 Python 协议、Java 编排及 Node 状态回归和必要构建。一次最终独立复审；修复本次问题。不优化供应商响应时间，不把离线通过宣称为真实模型/真机验收。

验收重点：改名不改跳转；无效引用不进入卡片；旧协议不收新字段；新指令执行一次；取消之后旧写入失效；连续补充与重启不丢内容；账号/API 切换不串数据；自然文案和卡片并存。
