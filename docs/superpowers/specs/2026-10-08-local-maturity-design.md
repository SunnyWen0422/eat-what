## 3. 数据要求

### 原件、身份、历史

- 原 Excel/ZIP/CSV 校验值前后一致；全部清洗写新产物，脚本可重复运行，输出目录不可覆盖已有版本。
- 保留菜谱 ID，禁止全库换 ID、按同名删除，禁止覆盖已有私人菜、历史计划/实际快照。
- 本地演练用户保持关联 ID，但身份字段匿名化；不携入真实微信 session、手机号、头像、token 或生产密码。匿名化盐和本地数据库凭据仅存在忽略目录。
- 生产迁移读取发布前的新快照和增量；当前备份只是本地演练基线。

### 独立可信状态

每道菜保存数据版本、原始内容指纹、材料身份、材料来源、用量来源、基准份数、步骤状态、营养来源、图片权利状态及人工核验记录。使用独立字段，禁止一个总分代替事实依据。

状态：`UNREVIEWED`（未核验）、`SOURCE_EXPLICIT`（给定原文明确描述）、`VERIFIED`（人工核验）、`UNKNOWN`（无依据）、`REJECTED`（排除的提取结果）。来源原文明确不等于实际做菜验证。结构完整不等于可信。

- 七段材料中的数字若只有统一赋值/菜名/常规补全依据，自动计算值为空；原值只作为可展开的来源记录保存。
- `快手/干锅/手撕/爽口/锡纸/脆皮/广式` 等明确描述词误提取，退出有效材料集合并保留排除原因；扩展词表必须有证据和回归样例。
- 同义重复如“猪里脊/肉丝”进入复核清单，不自动合并、不机械相加。不同处理形态和规格分开。
- 份数未知不能从统一 `2名成年人总量+15%冗余` 推定成两人；热量导入默认 0 显示为未知。缺价留空；真实实付与参考价格独立。
- 单菜时间是原文/加工估计/实测中的哪一种必须可辨；整餐总时长不能冒充并行烹饪实测。
- 菜系、早餐资格、口味、设备、人群缺失保留未知；普通忌口不包装成过敏安全保证。

### 产物和验收

全量输出标准化公开菜谱、材料事实、逐 ID 问题清单、修订前后对照、源校验值和统计审计。必须检查字段缺失、ID/整行/同名重复、单位、异常分布、引用和步骤材料一致性。

首批 50–100 道为**复核候选**，选择高频日常菜、不同类别/时长与早餐场景。只有具备配方来源、材料与步骤一致、份量依据或明确未知、图片使用状态以及人工审阅记录，才能进入可信主推池。实做验证另设状态；不能为了达到数量把未核验候选标成 VERIFIED。

## 4. 架构

Python 离线治理管线输出版本化公开数据；Java 的授权菜谱读取是应用事实来源。质量表补充事实与来源，保留旧 food 字段兼容和原始内容。Java 为公开菜和本人私菜按身份加载质量；前端只展示已核实值或未知状态。

新增 `dish_quality_profile` 存菜谱质量与材料事实 JSON，`dish_quality_revision` 存不可变版本修订证据。新迁移采用当前 manifest 后续独立版本，不修改已发布 SQL/checksum。未建质量表的服务不能伪报已验证。

采购预览首先读取质量事实：材料身份有效、用量可信、基准人数可信、单位兼容，四项同时满足才能 CALCULATED；否则保留材料名称、说明和人工核对入口，金额为空。没有新质量记录的私人配方遵守现有明确份数规则，且标记来源为用户输入，不伪装系统核验。

模型通过 Java 注入的授权候选和用户上下文读取公菜/本人私菜、菜单、偏好与近期明确实际记录；模型仅提出选择，Java 校验 ID、硬约束、目标日期和版本。正式与本机适配器使用同一请求结构。外部服务不可用时保持明确提示与手动/规则路径。

## 5. 迁移和本地环境

旧迁移 V3 calendar_sync / V4 custom_dish_receipts / V5 assistant_recipe_provenance 与当前 V3 meal_workflow / V4 meal_workspace / V5 shopping_prices 同号不同义。桥接依据真实列与索引，不按最高版本号推定。

桥接器仅对新建的本机隔离数据库工作：初始化独立 MySQL 进程/目录，读取备份数据，匿名化账户，保留旧对象，应用经过检查的新增对象/列，处理 source_date 和 source_meal_type 类型差异；未知血缘、非法日期、唯一键冲突、快照不明或数量不能安全承接即停止。重复运行不重复插入、恢复点明确。保留旧回执；不伪造新版成功回执；旧计划不转成实际吃过。

本机 API 绑定 127.0.0.1，数据库名固定前缀 `eatwhat_maturity_local_` 或 `eatwhat_maturity_test_`，生产地址拒绝。旧 `.local-v4` 保留，新环境单独目录与配置。前端 V4 开启、API 指向新本地服务。提供启动、状态、停止、重新导出微信纯净副本的说明。

## 6. 体验合同

- 登录等待真实 Promise；取消、超时、失败可辨；过期响应不更改新账号身份。
- “今天”随自然日切换；明确编辑的历史餐保留目标，能回今天；账号隔离和跨日草稿不能丢。
- 菜谱详情/收藏/菜单可加入当前餐；已有目标、锁定项、最多 10 道、条件与版本保护一致。
- 工作区唯一主要确认动作，组合工具移入低频入口；冲突动作名符合实际行为。
- 做饭版本冲突可返回当前餐重新进入；进度不能自动记为吃过。
- 日历实际记录复用持久原请求恢复，未知结果使用原请求键，重新进入不重复写入。
- 菜单先列可复用内容，编辑按需展开，“我的”可找到；统一私房菜/菜单命名。
- 回顾保留历史日期周期；空、请求失败、买齐分别给可执行下一步；技术指纹、编号渐进展开。
- 价格/份量未知在详情与采购同义；按钮、Sheet、大字、320px、键盘和安全区都实际验收。
