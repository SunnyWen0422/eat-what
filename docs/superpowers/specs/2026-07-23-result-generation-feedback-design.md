# 推荐结果页渐进反馈设计

## 目标

让推荐结果页在首次生成、重新生成、弱网降级和失败时始终给出准确反馈。已有方案不能因为重新生成而消失，任何请求都必须在有限时间内结束加载状态，迟到结果不能覆盖用户后来得到的新方案。

## 范围

- 仅修改推荐结果页的请求生命周期和显示状态。
- 复用现有 `recommendation-flow`，不改变推荐算法、后端接口或筛选条件。
- 保持收藏、换一道菜、保存到日历和滑动方案等既有行为。

## 状态模型

- `loading`：仅表示页面还没有可显示方案的首次生成。
- `refreshing`：已有方案时正在生成新方案；旧方案继续显示。
- `loadingStage`：当前生成阶段的短反馈文字。
- `generationNotice`：本地降级、空结果或刷新失败等非阻塞反馈。
- `generationVersion`：每次有效生成递增，只有当前版本可写入页面。
- `generationInFlight`：阻止同一时刻重复提交。

## 交互流程

### 首次生成

- 立即显示骨架和“正在分析你的偏好”。
- 800 毫秒后仍未完成，切换为“正在筛选合适的菜品”。
- 2500 毫秒后仍未完成，切换为“网络较慢，正在准备本地方案”。
- 8 秒仍未完成则结束加载，进入错误状态并提供“重新生成”。

### 重新生成

- 当前方案和底部操作栏保持可见。
- 顶部显示生成阶段提示；“重新生成”按钮显示忙碌状态并禁止重复点击。
- 成功后原子替换方案并回到第一套方案。
- 返回空结果或失败时继续显示旧方案，并提示“仍显示上次方案”。

### 降级反馈

- 后端方案不额外提示。
- 使用缓存菜品时显示“网络较慢，已使用缓存菜品生成”。
- 使用本地菜品时显示“已使用本地菜品生成”。
- 降级提示不遮挡方案，下一次生成开始时清除。

## 超时与竞态

- 页面使用 8 秒硬超时包裹完整推荐流程，防止本地菜品加载继续悬挂。
- 超时只结束页面等待，不要求取消底层网络请求。
- 超时后重试会产生新版本；旧 Promise 后续成功或失败都不能改变页面。
- 页面卸载时清理阶段计时器并使当前版本失效。

## 错误状态

- 首次生成失败：无方案，显示错误说明和重试按钮。
- 首次生成返回空：显示现有候选不足说明和重试按钮。
- 重新生成失败或为空：保留旧方案，显示非阻塞提示。
- 所有完成、失败、超时和页面退出路径都必须清理 `loading`、`refreshing` 和计时器。

## 验证

- 测试重新生成期间旧方案保持可见。
- 测试重复点击只发起一次生成。
- 测试首次超时结束加载并允许重试。
- 测试超时后的迟到响应不覆盖重试结果。
- 测试重新生成失败和空结果保留旧方案。
- 测试缓存/本地来源提示和 WXML 状态契约。
- 运行前端全量测试、仓库验证脚本和 `git diff --check`。
