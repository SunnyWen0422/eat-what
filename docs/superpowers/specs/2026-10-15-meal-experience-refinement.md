# 餐桌体验优化：实施规格

日期：2026-10-15。源码基线：`7977455b26213a1579f7c4f7f73b4426d12748ce`。

依据：本轮《功能地图与优化报告》、现有 V4 源码、用户确认的温暖餐桌 A / 轻透浮层 F。网页版个人数据保存在本浏览器，不具备小程序的助手会话与云同步能力。报告中的 72 分是体验评估，不是可靠性或在线服务可用率。

## 目标与顺序

1. 今天和菜谱优先展示菜品，减少反复出现的设置与说明。
2. 助手保留独立对话页，并通过当前餐与日历提供明确入口；本餐要求保持简短设置。
3. 整理保存、采购、做菜、实吃之间已有的跳转与反馈。
4. 全页面统一字体、控件、必要提示和窄屏/大字适配。
5. 在上述流程稳定后增加有明确作用范围的偏好反馈。

页面与流程按计划 A 实施；偏好反馈按计划 B 实施。两者独立交付，B 不阻塞 A 的交付；B 必须以 A 的最新提交为起点。

## 不变量

- 四个主导航保持“今天 / 菜谱 / 日历 / 我的”，不增加第五个助手导航或遮挡内容的悬浮入口。
- 菜品卡片页面、助手与其对话/推荐沿用 F；其他页面沿用 A。使用现有品牌色 `#28634E`、背景 `#F8F7F2`，不再整体换肤。
- 优先显示现有图片；无图或当前图片加载失败才显示分类图标。缩略图圆角 14px，详情主图 18px，保留 image source 与错误恢复，不修改本轮图片代理或证书策略。
- 复用 design/tokens.json：页面标题 24、区块标题 18、菜名/正文 16、辅助 13、注释 12；重要操作和正文不降为辅助字号。最小点击区 44×44、主按钮高至少 48。正文行高 1.5，长文 1.65。所有数值为缩放前逻辑 px，继续遵循现有 fontScale。
- 按压/列表/弹层动效使用现有 100/180/200ms；减少动态效果开启时不做位移动画。不能引入持续背景动画、多层模糊或额外动画依赖。
- 保存计划不等于吃过；查看最后一步不自动写实吃；勾完购物条目不自动开始做饭或写实吃。
- 未知结果恢复原请求；过期预览重新核对；版本冲突、账户切换、硬忌口、确认与取消行为全部保留。
- 价格缺失不猜、不填零；参考估算与实际支出分开。必要来源、形态、部位与未知用量不能为“简洁”而删除。
- 复制菜谱仍在编辑保存时创建，取消未保存编辑不创建副本。
- 新功能优先 V4，旧聊天仅保持兼容；本轮不新增助手服务端工具，不改模型上下文预算，不改数据库结构。
- 不部署、不上传小程序、不修改线上开关、不访问生产数据库。离线验收不用真实供应商模型；后续需要真实请求时先核对剩余预算，不能把过去预算视为无限授权。

## 页面决定

### 今天 / 本餐结果

保留日期、标题、横排餐次。人数与搭配变成一排两个明确的可点区域，分别复用原弹层。未生成时显示简短要求入口；已生成时改成“本餐设置”折叠区域，默认收起，内部仍能修改要求、筛选、用时和已有食材。“自己选菜”始终可达。

菜单放在设置摘要之后；保留换一道、换一套、锁定/撤销、保存和未知结果恢复。底部只有一个主操作，继续由 deriveWorkspacePresentation 决定；不为视觉简化重排同步失败和版本冲突的优先级。恢复错误不能藏进折叠区。

### 菜谱 / 详情 / 我的菜谱

首屏顺序：标题与来源切换 → 搜索和筛选按钮 → 一行可横滑的分类 → 菜品列表。高级筛选默认收起，已启用条件数量可见。首次教学不常驻占首屏，改到显式“使用说明”中；编辑常用菜单的作用范围提示必须保留。日期/人数只在底部已选栏显示一处。

已选栏无选择时不留空白；有选择时显示“本餐已选 N 道 / 查看”，可展开详情。菜名最多两行，完整名称在详情可读。详情标题与收藏/分享同一行顶端对齐；主操作随上下文显示加入本餐、查看本餐或开始做菜，不同时争抢主按钮。

### 助手

今天入口文案“聊聊这餐”，日历具体餐次入口同文案但携带该日期/餐次。菜品详情增加“问问这道菜”属于计划 A 的独立任务：通过本地一次性 handoff 传递菜品 ID 和待发送问题，不扩充服务端 entryScene 枚举，不自动发送，不偷偷加入当前菜单。

标题只出现一次。上下文摘要一行展示日期、餐次、人数和菜数；菜单默认折叠，展开后复用现有 assistant-card。空会话最多四个快捷项：安排这餐、换道菜、准备食材、看看安排；是否可用取决于当前菜单与能力，点击只填输入框，需要用户发送。已有输入时先确认是否替换，取消保留原输入。

语音入口在新版助手隐藏；旧兼容路径仍保留“抱歉，该功能暂不可用”的行为。只收起装饰性与重复信息，不隐藏待确认任务、来源、目标日期、采购勾选、过期提示、失败恢复和实际执行结果。卡片写入仍经过原确认处理，不允许快捷项绕过。

### 任务衔接

日历保存成功显示准确目标和“准备食材”；日历餐次保留“开始做菜”和“记录实际用餐”。采购页不从全部已买反推一顿饭：仅当条目有明确餐次来源时提供“查看对应餐次”，多来源先选择目标，无来源不显示做菜捷径。做菜完成仅提供“记录这餐”按钮，继续打开原实际用餐确认。

我的页面按“常用内容 / 偏好设置 / 账户与恢复”分组；管理入口仍按权限显示。统计保留真实记录口径，空态不宣称用户没吃饭。所有 27 条注册路由逐页检查，管理页面仅做公共样式回归、不重做管理业务。

### 网页

同步今天、菜谱、详情、日历、购物、我的的密度、字体和提示规则，复用已有回调和 IndexedDB 数据边界。网页没有助手时不渲染虚假助手入口；不把本浏览器记录描述为已同步微信。网页不引入本轮新增云服务。

## 后续反馈的范围

“换一道”仍直接换；菜品次级菜单新增“这餐保留”“这次想换”“这餐想省时”。保留对应现有 lock；想换对应现有 replace（不承诺永久不出现）；省时打开已有用时设置，不能自动猜具体分钟数。操作不默默改变长期偏好。

长期设置只复用已有偏好字段：菜系、标签、忌口食材、默认人数、避重天数、每道菜用时上限。整餐总时长不得直接写成每道菜上限。不支持单菜永久黑名单，因此不显示“永不推荐这道菜”按钮。用户主动进入并保存偏好后才提示已保存；网络失败不提示成功。

## 验收与评分

- 正常字体、390×844 固定夹具：今天已生成状态至少看见两张完整菜品卡；菜谱至少三条可识别菜品（图片、菜名和操作可见）。保留必要错误时允许信息区增高，不用隐藏错误换指标。
- 320/390/430 宽度 × 字体 1/1.3/2，网页另加 1280 宽；长菜名、无图片、图片失败、空菜单、十道菜、键盘、离线、未知结果、版本冲突分别覆盖。大字不要求同样首屏数量，要求内容和操作完整可达。
- 实际界面与受控夹具截图分开保存；浏览器/WXML 近似预览不能代替微信开发者工具或真机证据。
- 列出每一页的入口、A/F 样式、状态、截图、缺口；真实模型、真机和线上未测时明确未测。
- 同口径重评：视觉15%、内容20%、层级15%、文案10%、反馈10%、可访问性10%、助手可发现性10%、动效10%；不给未验证维度虚构加分。
- 后续可邀请约10位目标用户完成选餐、保存、采购、记录四任务，目标无指导完成率≥90%；这是待开展的用户研究，不能由 agent 点击替代。
