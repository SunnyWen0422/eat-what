# 移动端用户菜品后台设计

## 目标

保留“我的”页面连续点击版本号五次进入后台的隐藏入口，并把现有后台升级为适合微信小程序移动端使用的用户管理和代用户添加菜品工具。

## 权限边界

- 入口仅在当前登录用户的 `/users/info` 返回 `isAdmin=true` 时响应五次点击。
- `/admin/**` 继续由登录拦截器和 `ADMIN_USER_IDS` 双重校验；前端隐藏入口不作为安全措施。
- 管理员只能在目标用户存在时创建其自定义菜品，只能删除明确属于该用户的自定义菜品。
- 删除使用数据库 `DELETE`，不能把 `user_id` 清空后意外转成系统菜品。

## 页面结构

### 用户列表

- 顶部固定搜索框，可按用户 ID、昵称或手机号搜索。
- 每项显示昵称、用户 ID、手机号、状态、注册时间和自定义菜品数。
- 首次加载、空结果、失败重试、加载更多和下拉刷新都有独立状态。
- 后端分页，默认每页 20 条；搜索变化后从第一页重新加载。

### 用户详情

- 顶部返回按钮和用户概要。
- 菜品列表显示名称、分类、菜系、标签与烹饪时间；删除按钮有二次确认。
- 页面底部固定“添加菜品”按钮，并为 iPhone 安全区留出空间。

### 添加菜品

- 使用全屏表单而非居中弹窗，避免手机键盘遮挡内容。
- 菜品分类使用五项分段选择；菜系使用选择器；标签使用多选按钮。
- 菜名、食材和步骤为必填；烹饪时间可选，限制 1-240 分钟。
- 保存按钮防重复提交，失败时保留全部输入；成功后返回详情并刷新列表。

## 后端结构

- 新建 `AdminUserService`：分页边界、关键词规范化、用户总数和列表查询、目标用户存在性校验。
- 新建后台用户摘要和分页 DTO，避免控制器拼装无类型 Map。
- `UserMapper` 使用 `LEFT JOIN food` 一次性统计每个用户的自定义菜品数量，替代逐用户查询。
- `AdminController` 仅负责授权、参数接收和 HTTP 响应。
- `CustomDishService` 校验分类、字段长度、烹饪时间和元数据编码，并真正删除用户菜品。

## 错误与兼容

- 页码小于 1、每页数量越界、目标用户不存在、菜品字段非法均返回 400 或 404。
- 保持原 `/admin/users` 响应中的 `data` 字段，同时增加 `list/page/pageSize/total`，兼容旧前端。
- WXML 不依赖第三方组件，尺寸使用 `rpx`、弹性布局和 `env(safe-area-inset-bottom)`，支持常见窄屏设备。

## 验证

- Java：授权、分页参数、搜索、目标用户校验、归属创建和真实删除。
- Node：五击入口、分页合并、搜索重置、表单校验、完整请求载荷、防重复提交和移动结构契约。
- 仓库：JavaScript/JSON/Java 测试、SQL/脚本检查和 `git diff --check`。
