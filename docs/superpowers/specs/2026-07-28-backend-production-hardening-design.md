# EatWhat 后端生产化安全重构设计

**状态：已确认，按方案 1 实施**

## 目标

在不改变现有小程序接口路径和核心数据模型的前提下，消除当前已识别的高风险路径，并为后续上线建立可验证的安全、迁移和运维边界。

本次重构针对以下问题：微信登录敏感信息日志、默认 Token 密钥、禁用用户仍可使用旧 Token、AI 聊天无配额、开放 CORS、缺少 Java 健康检查、破坏性数据库脚本、推荐职责边界不清和自定义菜谱 CRUD 不完整。

## 约束与非目标

- 保留 Spring Boot、FastAPI、MySQL、Nginx 四部分部署拓扑。
- 保留现有 `/api` 接口路径和前端请求格式；需要增加能力时采用兼容性新增。
- 不在本次代码变更中连接生产数据库、执行生产迁移或上传服务器。
- 不引入 Redis、消息队列或微服务拆分；当前单实例服务器规模不需要这些额外依赖。
- 不承诺消除未知漏洞；验收范围是已识别风险和对应回归测试。

## 目标架构

Spring Boot 继续作为业务 API、认证、授权和所有数据库写入的唯一入口。FastAPI 只负责 AI 聊天、RAG 和降级生成，不直接写入业务表。Nginx 负责 HTTPS、静态资源和反向代理，数据库迁移通过版本化脚本管理。

### 安全边界

1. 所有生产秘密必须来自环境变量或外部配置，缺失时 Spring Boot 启动失败。
2. 登录响应和用户信息响应使用公开 DTO，不返回 openId、unionId、sessionKey 等内部身份字段。
3. 每次需要登录的请求在 Token 校验后检查用户状态；禁用用户立即收到 401/403。
4. AI 聊天保留匿名兼容，但匿名和登录用户均受按身份/IP 的请求速率、并发数和请求大小限制。
5. CORS 来源来自配置白名单，支持实际使用的 HTTP 方法，包括 PATCH；生产 Nginx 不再写死 `*`。
6. 微信、AI、数据库访问日志只记录请求 ID、耗时和错误码，不记录密钥、session_key、完整请求体或完整第三方响应。

### 可观测性

- 引入 Spring Boot Actuator，提供 liveness/readiness/metrics。
- 保留现有请求 ID，并在 Java、Nginx 和 FastAPI 日志中关联。
- 为 AI 调用、限流、数据库失败和迁移版本增加结构化事件字段。

### 数据库发布

- 新增版本化 migration 目录，所有未来结构变更使用递增版本。
- 现有建库脚本标注为开发初始化或一次性数据处理脚本，禁止生产流程直接执行带 DROP 的脚本。
- 迁移在执行前检查数据库名、当前版本和备份标识；本次只增加代码和迁移模板，不执行生产迁移。

### 业务边界

- `/api/recommend` 继续由 Java `RecommendationService` 提供唯一主结果。
- FastAPI `/recommend` 保留兼容测试和内部调用，但不再作为小程序主入口。
- 自定义菜谱补齐用户自有资源的更新和删除接口，所有查询和写入都绑定当前用户 ID。

## 分阶段实施

### Phase 1：安全基线

- 敏感日志清理与公开用户 DTO。
- 默认密钥 fail-fast。
- 用户状态校验。
- AI 限流、并发和请求大小保护。
- CORS 配置化和 PATCH 支持。

### Phase 2：生产运维基线

- Actuator 健康检查和指标。
- 统一错误码、请求 ID 和关键日志字段。
- 迁移目录、版本表和生产执行前置检查。

### Phase 3：业务边界收敛

- 自定义菜谱 PUT/DELETE。
- 推荐主实现和 FastAPI 职责说明。
- API 契约与安全回归测试补齐。

## 兼容性与失败策略

- 现有成功响应字段保留；公开 DTO 只移除不应暴露的身份字段。
- 限流返回 HTTP 429，并提供 `Retry-After`；前端继续使用现有错误提示逻辑。
- AI 服务不可用时保持当前降级回复，不阻塞菜品和购物清单功能。
- 缺少生产密钥时拒绝启动，而不是使用弱默认值。
- 数据库迁移失败时保持旧版本服务运行，禁止自动执行破坏性回滚。

## 验收标准

- 代码扫描不再发现微信响应、Token 或数据库密码的明文日志。
- 缺少生产秘密的 Spring Boot 启动测试失败，提供完整配置时启动测试通过。
- 禁用用户的有效 Token 无法访问受保护接口。
- AI 匿名和登录请求超过阈值返回 429，正常请求仍可用。
- CORS 只允许配置来源，并正确处理 PATCH 预检。
- Java Actuator liveness/readiness 返回可解析 JSON，数据库不可用时 readiness 失败。
- 迁移脚本可在隔离数据库重复执行，不包含无保护 DROP。
- 前端 96 项、Java 现有测试、Python 测试和隔离 MySQL 集成测试全部通过。

## 回滚

- Phase 1 的新增控制均可通过环境开关临时放宽，但不恢复敏感日志和默认密钥。
- Phase 2 只新增健康检查、指标和迁移工具，不改变业务表数据。
- Phase 3 的新增接口不影响旧接口；必要时只回滚新增路由和对应前端调用。
