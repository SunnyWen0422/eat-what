# EatWhat 界面与交互长期规范

更新：2026-10-20。依据用户连续多轮页面反馈整理，适用于小程序一级页、二级页、
弹层、助手卡片及新功能。这里记录以后应遵循的取舍，不是一次性修改清单，
也不表示所有页面已经通过真机验收。用户后续明确决定优先于本文；
带日期的验收记录中的旧方案不能覆盖新决定。

## 1. 优化的顺序

先明确用户此刻要完成的动作，再整理信息与控件，最后处理视觉和动效。
每次按以下顺序判断：

1. **动作是否清楚：** 看见入口就能理解点后发生什么，必要操作实际可达。
2. **信息是否重复：** 标题、描述、状态、按钮各承担一种职责，同一意思只出现一次。
3. **布局是否紧凑：** 能在一至两行表达的缩略信息，不用多层卡片、长按钮和说明堆高。
4. **对齐是否一致：** 图片、文字块和操作组横向排列、整体垂直居中；同级内容共用起始线。
5. **主次是否可辨：** 用字号层次、深浅、边界和留白区分，不依赖大号粗黑字。
6. **是否保留真实行为：** 精简展示不能丢失保存、确认、取消、错误恢复、图片或跨页同步。

## 2. 视觉语言

| 项目 | 持续规则 |
| --- | --- |
| 整体风格 | 普通页面保持温暖餐桌风格；菜品与饮食助手使用轻透浮层，避免独立页面突然换一套语言 |
| 默认字号 | 标准比例 `fontScale = 1`，不额外默认放大；具体字号取共享设计令牌 |
| 字重 | 正文 400，菜名、分区标题、选中项、主要按钮最多 500；不回到 600/700/bold 粗黑体 |
| 主页面标题 | 深松绿、轻宋体系统字形和少量字距，文艺但醒目；正文与二级页不全部换成宋体 |
| 分割线 | 灰绿色 `divider = #B8C5B8`，标题下及列表间清楚一致；控件底色使用独立令牌 |
| 控件辨识 | 筛选和普通次按钮不能浅到看不出可点；主按钮深绿白字，次按钮有可辨边界或浅色底 |
| 轻量图标 | 返回、用时等工具栏图标透明融入背景；返回用箭头，时间用闹钟，不机械给所有按钮加色块 |
| 动效 | 默认开启，偏好中不设开关；助手可用渐变细边框、炫彩文字及短过渡，避免大块装饰 |
| 点击区域 | 视觉可以轻薄，触控区不能缩没；一般至少 44px，主要按钮沿用 48px |

“颜色更明显”和“按钮融入背景”适用不同控件：筛选状态和主要操作需要辨识，
返回/工具图标无需底色。不能把某个截图里的局部要求机械套到所有页面。

## 3. 内容密度与菜品展示

- 菜品列表默认两行缩略信息：菜名一行、必要分类或时间一行；图片、两行文字整体、
  收藏/换菜按钮共用垂直中心，不把操作另放第三排。
- 已选菜品弹层以真实图片＋菜名为主体，缺图或加载失败才用分类占位。
  长菜名最多两行，右侧小号红色减号；底部“继续选菜 / 查看本餐”同排。
  菜谱、详情和收藏入口复用同一展示与原有移除规则。
- 普通食材条目两列，特别长的条目可跨列；不再因默认大字退回整页单列。
- 食材名称、分量、备注分清层次。购物清单、按菜查看、参考价区都要薄，
  不重复显示食材名，不塞入具体做法、内部来源字段或冗长加工描述。
- 删除所有“用量待核对”等无效占位；缺用量/参考价就留空，不猜数值、不补零。
  有效的烹饪提示放在合适位置，精简不等于丢弃有用原方信息。
- 做法只显示一套步骤号；显示层清理原文明确编号，不改原菜谱、用量、小数、
  温度、时间、图片顺序或阅读进度标识。

## 4. 首页、菜谱、日历与个人页

- 首页“个性化 / 自己选菜 / 闹钟”一行，取消与个性化重复的补充要求白条；
  已有本餐要求仍能查看和编辑。饮食助手是主推入口，紧凑但醒目，文字可炫彩。
- 菜谱标题旁放带放大镜的搜索框，不再放右上说明入口。
- 常用菜单用“选菜 → 命名保存”的明确流程；从本餐保存时沿用已选菜品。
  少用长句文本按钮，避免多处反复介绍“常用菜单是什么”。
- 日历保留日期选择与餐次卡，不重复“某年某月某日的三餐”；空餐次简写“没有记录”。
- “我的”顶部头像、昵称和编辑入口紧凑对齐，不重复页面标题或登录状态介绍；
  常用人数输入保持单行薄控件。餐次选择采用清晰、紧凑、有选中态的形式。

## 5. 饮食助手：视觉突出，行为具体

- 空会话不放装饰四角星。左侧四行快捷文本：两项推荐、一项查看安排、
  一项查看今天实际饮食健康程度；点击预填，用户可修改再发送。
- 日期/餐次栏及展开的本餐设置固定在聊天滚动区外。长设置独立滚动，
  聊天、设置和底部输入框互不带走；键盘出现时仍可操作。
- “本餐设置 → 修改”必须打开真正的设置表单，不能只改输入框文字。
  设置应用、重新推荐、保存日历是不同动作；取消设置不改聊天草稿。
- 等待必须真的动起来，用圆环/提示点及分场景轮换短句表达正在生成一餐、
  查看安排、整理饮食回顾等。只描述真实处理状态，不假装已经查到或保存成功。
- 不向用户展示“核对原请求”等内部用语，改为“继续查看结果”等可理解动作；
  内部仍保留原请求身份和恢复约束。
- 提示集中在输入框上方：对应失败才显示“已保留本次输入”，实际恢复菜单才显示
  “已恢复上一版菜单”。图标和文字居中对齐；正常时不常驻，也不把旧提示带入新请求。
- 菜单同排“查看 / 撤销 / 采用”：查看展示菜单而非展开设置；
  撤销有明确入口，五角星仅表示收藏；采用保存对应日期餐次，有原安排时确认替换，
  真实保存成功才显示“已采用”。
- 助手生成的菜单与首页共享同一工作区。旧卡片不能覆盖新版本，回读失败可以恢复；
  恢复不能重发已完成生成、覆盖新输入或与本地设置恢复互相阻挡。

## 6. 购物清单：减少入口，让操作直接

- 添加食材只提供自定义表单：名称、分量、备注；移除旧的日历/菜谱添加选择层。
- 底部“复制菜谱”复制排版清楚的食材及用量清单，缺用量留空；不复制重复说明。
  这里的复制到剪贴板与“编辑菜谱副本”是不同能力。
- 右上垃圾桶进入删除模式，各材料右侧显示红色减号；
  删除模式还要有“全部删除”，先确认范围，取消不写入。
- 垃圾桶旁的购物篮勾选图标表示“一键全部已购”，先弹“是否全部已购”，可选是或取消；
  不是外部购买，不自动新增实付。
- 买齐后的提示和返回入口上下排列，避免长说明和按钮左右挤在两列。
- 官方参考价与实际支出独立；缺参考价不造值，真实 0 元实付有效。

## 7. 后续修改的验收方法

检查同类入口，而非只改用户指出的一张图：一级页、二级页、弹层、助手卡片及空态
都要考虑横向、竖向对齐和主次层级。共享组件优先统一修复。
同时查看长菜名、缺图、空数据、忙碌/禁用、失败、恢复、已保存、旧版本等状态。

视觉在原生工具中测实际尺寸、居中和滚动；等待动效用不同时间采样验证，
仅有 CSS 声明或单张截图不算动画验证。源代码改动同步样式模板和生成输出。
交互检查覆盖原处理器、确认/取消、真实回执、跨页同步及输入归属，
以适用的定向回归验证；纯文档更新只检查内容一致性和链接。

本地合成数据、前端测试、真机、模型、数据库和部署证据分别记录。
历史通过数和旧截图不能作为新状态已验证的证明，也不授权上线。
