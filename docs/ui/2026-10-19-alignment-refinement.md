# 2026-10-19 页面对齐与操作菜单修正

## 范围与用户标准

基线为 `658d6cc`。用户指出更多餐单操作按钮过大、助手入口下移、页面文字和同级按钮不对齐。本次只修改小程序呈现；保留 A/F 风格、业务处理方法、禁用条件、危险操作确认和未知结果恢复入口。不修改后端，不发布。

## 问题与修复

- 更多餐单操作误用了全宽操作按钮，日期 picker 和子 view 重复使用相同 padding；标题和说明是连续内联 text。改为统一左对齐列表，值和箭头靠右，说明另起一行；保留顶部关闭和遮罩关闭，去掉无提交行为的重复“完成”。
- 小屏及大字号强制标题占满整行，导致助手下移。助手与标题放在同一行独立操作组；更多移到顶部清单旁。长标题在自己的区域换行，不挤走助手。
- 添加食材、清单操作、菜谱详情更多菜单有相同按钮堆叠，按相同列表规范调整。清单删除仍走原确认流程。
- 全局标题与阅读段落明确使用块级布局。图标宿主使用 inline-flex，避免行盒基线影响；并排操作和 ui-button 宿主拉伸对齐；确认按钮文字在按钮内水平、垂直居中。
- 日历、购物清单标题区原先顶部对齐，使较小操作文字视觉下沉，改为居中对齐。

## 验收方法

复用原生隔离项目，全程合成菜品和账号，禁止真实请求。逐页读取真实初始 data，再注入样例，避免预览遗漏默认菜单与状态。浏览器仅作为不同宽度/字号的适配检查，不替代原生或真机证据。对新增列表实际测量左边缘、行高以及助手与标题中心位置。相关交互检查限定到工作区导航、组合流程和共享组件，不运行全量业务测试。

本机截图、逐页状态、几何检查和测试日志保存在工作区 `work/alignment-refinement-20261019/`。最终统计以该目录的报告为准；不存在真实用户、真机、生产服务和模型验证。

## 后续页面交付规范

1. 页面检查必须包含次级菜单/弹层、长文案和大字号，不能只看首页正常状态。
2. 导航菜单优先列表行；真正的提交/确认才使用强调按钮。44px 触控区域不要求画成整块大按钮。
3. 明确同级操作的共同轴线，检查文字/图标中心、行高及左右边缘。无溢出不等于美观或对齐。
4. 预览需有完整默认 data 和代表性内容；空白样例或表达式异常不得算作该页面验收通过。
