# A 温暖餐桌 / F 轻透浮层：实施与验证记录

日期：2026-10-13。基于 `codex/v4-meal-workspace-green-20261003`，实施起点 `51abb19927dc33be8c17db31de9a5adc3ff725a8`。本轮仅本地修改，未提交、推送、上传或部署。

## 已实现

- 小程序菜品卡、菜单、菜谱、收藏、个人菜谱、详情、日历菜单和菜品管理区域采用 F。采购确认的按菜区域采用 F，食材汇总保持 A。助手整页、对话、推荐、确认卡和助手历史采用 F。
- 共享渐变为 `#E4EEDA → #F5ECE2 → #D7E9E3`；卡片为半透明白色、16px 圆角和轻阴影。没有为每张卡叠加模糊滤镜。
- 保留原菜品图片来源，优先显示圆角照片；缺图与加载失败回退分类图标。网页从当前公开菜库读取展示图片，图片映射不进入历史快照、推荐事实或导出备份；导入数据携带的任意图片地址不会自动加载。
- 网页同步 A/F 字体、色彩、按钮和菜品层级；人数与搭配、低频本餐操作、来源资料按需展开。保留忌口约束、资料不足、错误、未知写入、恢复入口及本地存储边界。
- 设置、资料、筛选、统计、同步、购物食材行、编辑表单及管理工具保留 A。烹饪步骤页为阅读工具，保持 A。
- 网页当前没有会话助手功能，本轮没有新增这项业务能力；小程序助手的确认写入、撤销和恢复协议保持原有行为。

## 修复的实际问题

1. 用户反馈的 `assistant-card/index.json` 将组件指向不存在的 `ui-icon/index`；同一文件的 `ui-button/index` 也有问题。已改为真实组件 basename，并增加全仓组件引用完整性检查。单独 WXML/WXSS 编译不足以发现此类注册路径错误。
2. 微信默认按钮宽度导致助手输入框被挤压、推荐菜名异常换行。对输入、发送、语音、返回和菜品行明确宽度与伸缩关系；普通与 2 倍字号原生截图复验。语音仍显示暂不可用，未接入模型服务。
3. 菜品行反馈为空时传入 null 引发组件类型告警，改为显式空字符串。
4. 独立审阅发现网页详情遗漏部分质量信息，以及个人菜品、采购按菜区缺少 F 背景。已保留质量说明折叠入口、补足局部背景并通过相关回归。仅内部代码转成可理解文案，不将未审核数据标成已审核。
