# 个人资料与购物清单精简

本轮根据用户提供的长昵称、旧食材来源文本截图修改。仅涉及小程序及共用购物展示逻辑；不修改服务端、线上数据或价格计算口径，不部署。

## 用户结果与范围

- 我的：去掉页面内重复的“我的”和“已登录”，头像、昵称、编辑图标同一行。长昵称最多两行，编辑入口保留完整辅助标签。
- 食材汇总、按菜查看、确认食材：以食材名和已有用量为主体，正常字号每行最小 52px；名称 14px、用量 13px，点击区域不少于 44px，随系统字体放大。
- 不再显示“用量待核对”等占位文字。缺失用量为空；已存的原方明确数量可以阅读，但不因此被标记为已确认，不参与原先禁止的自动合计和估价。
- 管道分隔来源里的角色、步骤、成人口径、冗余不直接显示。去皮切丝等做法从主列表去掉；去骨、切片、里脊、五花等采购形态/部位区别仍保留。食材身份、原来源、原始备注及质量标记不改写。
- 费用默认折叠；展开只显示两个合计、食材名称、可用单价及真实报价日期、记录支出入口。无报价说明集中显示一次。实付与参考价继续独立，真实 0 元实付仍有效。
- 底部“复制菜谱”复制当前待买/已买标签下的食材，按菜名及餐次分组、逐项编号，缺失用量不补字或补 0。没有内容时不覆盖剪贴板；复制失败可重试。
- 右上角垃圾桶进入逐项删除模式，右侧红色减号删除食材，顶部“完成”退出。汇总行删除本标签下该行的来源；按菜行仅删除当前菜的对应条目。
- 餐次来源采用日期图标、简短日期/餐次及数量，展开为日期与餐次对齐的选择行。选择仍跳转到原餐次，不伪装成清单过滤。

## 写入与恢复约束

| 情形 | 处理 |
| --- | --- |
| 进入/退出删除模式、取消删除 | 只改变展示，不写服务端 |
| 确认删除 | 固定确认时的账号、版本和目标 ID；多来源逐项串行使用回执版本 |
| 二次点击 | 确认和提交期间拒绝重复触发 |
| 账号切换/页面离开/确认前版本变化 | 不继续旧目标的写入 |
| 明确失败/版本冲突 | 停止后续删除，沿用已有失败或冲突处理 |
| 超时、断网、无可靠回执 | 原请求 ID/版本留在待确认草稿，不伪造删除成功 |
| 多来源部分完成 | 已成功删除保留，后续停止，剩余条目仍可见；提示完成数量及未完成部分 |
| 原请求重试 | 回执必须证明目标已不存在，不能仅以版本号增加宣称成功 |

编辑框用量也采用干净的展示文本。打开、取消或仅改名称不把展示文本提交为新的用量；只有明确编辑用量才发送该字段。最后一个食材来源删除时，其实付记录的既有服务端生命周期保持不变。

- 购物清单的底部“添加食材”直接打开表单，去掉中间的来源选择面板及空清单中的日历添加入口。
- 表单仅保留食材名称、分量、备注。名称和分量必填，备注可空；分量仍接受“2个”“500克”“适量”等原有文本格式。
- 空清单只保留一个主要添加按钮。已有食材时与“复制菜谱”并列；取消不写入，提交期间不能重新打开表单清空输入。
