# 菜谱、个性化与常用菜单体验调整

日期：2026-10-19。状态：本地实现，未推送或发布。本记录承接同日的对齐及饮食助手入口调整。

## 用户结果与范围

让用户能找到菜、看清筛选条件，并沿“新建常用菜单 → 选菜 → 命名保存”完成操作。保留温暖餐桌 A 的表单和轻透浮层 F 的菜品卡片。涉及小程序公共组件、菜谱浏览及二级页、本餐筛选、长期偏好、今天／结果页共享入口；没有更改网页端、后端、接口或数据库。

## 已实现的交互

- 菜谱分类改为左侧竖栏，菜品区域独立滚动，沿用搜索、分页和返回滚动位置逻辑。
- “筛选”入口改为“个性化”，较小的展开／收起文字独立右对齐。说明入口采用小图标，不再占用大文本按钮。
- 本餐筛选、菜谱筛选及长期偏好的选项采用共同的紧凑标签：普通字号为 13px，选项与数量同字号，触控区至少 44px；弹层选项换行排列。未选项使用可辨识的灰绿底与边界，选中项为深绿白字，排除项为深红白字。
- 菜谱及本餐筛选的清除操作移到标题右侧垃圾桶。菜谱清除仍保留搜索、已选菜品及食材排除项；本餐清除仍清除临时条件，不改变长期偏好。
- 菜品缩略卡片采用两行文字，图片、文字组和右侧操作组共用垂直中心线。菜名与摘要紧凑排布，收藏与选入／换一道保持并排，不再另起第三排。长菜名使用省略号，完整名称保留在详情与辅助标签中；必要反馈仍可换行。图片优先、圆角与失败占位保留。
- 饮食助手的文字采用深青绿／蓝／紫／暖棕渐变，沿用右上角胶囊边框及浅背景；不支持渐变裁切时保留品牌色，禁用时使用清晰的次级文字色。

## 常用菜单

1. 列表与空状态底部提供“＋ 新建常用菜单”，先打开全部菜谱的独立选菜状态，不再让用户面对 0 道菜的命名表单。
2. 选菜时用简短状态条标明“新建／编辑常用菜单”；选入按钮显示“选入／已选”，辅助标签说明添加到常用菜单而非本餐。
3. 底部固定显示“已选 N 道”及“下一步”。没有菜时不可继续；保存结果待核对时仍可打开原请求。
4. 命名页只保留名称、人数、已选菜品与“调整菜品”。底部保存按钮持续可达，编辑既有菜单时保留“另存新菜单”。去掉重复标题、普通状态下的内部快照／模板说明、长段引导。
5. 已有菜单的详情保留“用作本餐菜单”为主操作，编辑／删除为次级列表行；删除仍使用原确认流程。
6. 从今天页面“存为常用菜单”进入时，直接沿用当前菜单的菜品和人数命名，无需重新选菜。

## 状态和业务边界

| 状态 | 保留行为 |
| --- | --- |
| 新建、调整菜品 | 独立模板选择，不写入本餐草稿或日历；名称、人数和菜单身份保留 |
| 输入未保存时离开 | 原有保留／放弃确认继续有效 |
| 保存成功 | 写入原菜单 API，显示“已保存到常用菜单”；恢复原本餐选择 |
| 保存结果未知 | 输入及选择只读，重试原请求；新建入口不能覆盖原请求 |
| 版本冲突、菜品变化、不可用 | 保留实际错误和重新读取入口；显示需核对的菜谱内容 |
| 删除结果未知 | 保留原删除核对入口，不因列表中不存在就宣称成功 |
| 账号／服务／目标变化 | 沿用原有所有权、版本与晚到响应检查 |

未增加新服务、自动写入或新的模型调用。

- `experience-personal-recipes.test.js`、`personal-recipe-pages.test.js`：121 项通过。新增回归覆盖新建选菜后命名、未知保存恢复、返回选菜保留输入及取消不写入。
- `experience-components.test.js`、`experience-recipe-selection.test.js`、`recipe-browsing-maturity.test.js`：105 项通过。覆盖现有选择、组件和浏览边界。后续纯样式收尾复用这些行为结果。
- 同次筛选与共享组件的其他定向检查，以及首页入口的既有检查通过；不把重叠测试数相加为独立覆盖。
- 微信开发者工具隔离项目取得 10 个相关场景原生截图，命名页输入框垂直对齐修正后另行补拍。实点检查通过分类切换、两种清除入口，以及新建／选入／下一步／返回调整后保留名称。使用合成数据与读取替身；未通过原生点击执行真实保存。
- Chromium 对实际 WXML/WXSS 的辅助适配检查共 60 个场景组合：15 个场景 × 320/390px × 普通/1.5 倍字号，无页面宽度溢出或表达式错误。大字号卡片调整后仅补跑受影响场景。
- 开发者工具自动化在附加的大字号截图及属性读取阶段发生超时；已完成的点击与正常字号原生截图单独保存，未把未完成步骤记为通过。大字号最终证据是浏览器辅助排版检查，不能替代微信真机。
- 样式模板与生成 WXSS 一致，差异格式检查通过。不运行全量测试、不连接生产服务或模型。

工作区证据目录：`work/recipe-personalization-20261019/`（不进入仓库）。`index.html` 提供实际原生截图与操作路径；`native-menu-actions.json`、`native-actions.json` 保留已完成动作，`fallback-layout-results.json` 记录辅助适配结果。

## 后续维护

修改样式应编辑 `design/` 源模板并同步生成 WXSS。涉及常用菜单的入口必须复用同一模板编辑状态，不得把本餐选择直接当成常用菜单编辑器，也不得为了减少文字而移除真实失败或恢复入口。

## 同日补充：标签辨识度与卡片密度

- 标签不再使用接近页面背景的底色。普通项边界与选中实底采用公共样式，覆盖本餐筛选、菜谱个性化与长期偏好。
- 共享菜品行覆盖今天、菜谱、常用菜单详情、收藏、日历详情、我的菜谱及兼容结果页。两行文字作为一个整体居中，不能把按钮贴到底边或用过高的摘要行撑开文字间距。普通示例卡片约 80–82px 高；必要反馈允许增高。
- 左侧分类菜谱及窄屏／大字号优先显示简短时长，预计时长保留“约”；没有可靠时长只显示分类，不造数。大字号选菜操作采用勾选／加号图标并保留完整操作辅助标签。
- 本次 55 项组件与图片相关定向检查通过。40 个浏览器辅助排版场景覆盖 320/390px、普通/1.5 倍字号及相关页面；最终共享卡片的 28 个组合中心线测量通过。原生工具另有实际截图、居中测量和合成点击证据，详见工作区 `work/compact-cards-20261019/`。不以浏览器结果代替真机验收。
- 定向原生点击验证选入不误开详情、菜品主体仍进入详情、新建后下一步及返回调整保留名称/选择。未执行真实收藏、保存、数据库或模型请求，没有推送或发布。
- 额外的组件选择器静态扫描仍报告未改动的 `meal-card` 样式中既有选择器问题（`button.card-navigation` 等）；本次未扩大范围修改，不宣称全库静态检查通过。前一轮“所有缩略文字必须换行”的静态断言已按此次用户要求更新为“摘要可截断，必要反馈仍完整可读”。
