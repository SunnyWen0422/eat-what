# 一级、二级页面对齐复核

日期：2026-10-19。范围为当前小程序的 27 个路由，以及筛选、常用菜单、菜谱编辑、采购、日历记录、助手卡片等代表性状态。保留本轮之前的工作区修改；本次不涉及后端、生产数据或发布。

## 对齐约定

- 页面标题、分区标题、正文和辅助信息使用对应层级；同级表单标签使用相同字号、字重和间距。
- 同一内容区域的标题、正文、输入控件边界共用左边缘；控件内部文字保留一致内边距。
- 菜品图片、文字块、操作组共用垂直中心线。普通卡片保持两行缩略信息，长菜名可省略，详情和辅助标签保留全名。
- 换菜和收藏并排；同组按钮等高且文字居中，不能因窄屏掉到卡片下方。
- 单行原生 input 不使用垂直 padding 推动文字；textarea 保留阅读所需的内边距。
- 多行说明不强制与单行内容共用基线；保证组内层级和组间间距，不能用固定高度裁切必要错误与恢复信息。

## 已修正

1. 管理页标题与数量改为垂直居中，保留长标题换行。
2. 管理筛选 picker 和 input 使用相同外框高度、字号、左右间距；内层使用明确类名，去除双层边框，箭头靠右。
3. 审计记录标题改用专属类名，避免通用 `.action` 样式添加多余缩进和分隔线。
4. 管理编辑表单单行输入恢复垂直居中；标签和二级标题统一层级。
5. 添加菜谱的分类标签独立成行；选项复用共享标签样式和触控区，换行后仍从同一左缘开始。
6. 饮食助手餐次信息与消息区域左对齐；当前菜单卡片在窄屏下将换菜和收藏保留在同一行。菜名最多两行，仍能点击进入原菜谱详情。
7. 复制日历安排的日期与餐次之间增加一致间距，消除输入框贴边。
8. 日历餐次组件移除不符合组件选择器约定的标签选择器，改用显式类名；保持原有操作和外观。

## 证据与限制

- 27 个路由取得微信开发者工具原生截图，补充二级状态并对修复处重拍。使用隔离项目、合成内容，网络与持久写入被隔离。
- 浏览器辅助适配共 60 个场景、240 个组合（320/390px × 普通/1.5 倍字号）。复用未变部分，修复后只重跑受影响场景；最终没有文档宽度溢出、表达式错误、被裁切按钮或小于检查阈值的按钮。
- 原生助手菜单在普通和 1.5 倍字号下，图片、菜名、操作组中心线最大差值小于 0.01px。管理筛选内框与输入框仅有边框对应的高度差。
- 74 项相关组件、助手卡片和原生组件约束检查通过。未重跑全量业务测试。
- 样式源模板和生成 WXSS 一致；本次修改不改变保存、删除、收藏、换菜或查询的处理函数。
- 浏览器适配不等同原生；原生模拟器不等同 Android/iOS 真机。长页结合浏览器完整内容与原生视口检查，不宣称覆盖所有数据组合、系统字体或键盘场景。本次没有真实保存、模型调用、生产操作、推送或发布。

## 后续防回退

修改共享样式时先查直接使用者，再查同名类的其他页面；避免 `.action` 一类泛名污染文字。原生 picker 内部有包装层，依赖直接子选择器可能无效，优先给可见内层显式类名。验收必须包含二级编辑态和有操作的助手卡片，不能仅以首屏、空卡片或无溢出断言结论。
