# 吃什么 V4｜装饰、图标与无效元素专项审视

日期：2026-10-07。状态：已完成源码清点和设计处置，尚未实施。

用户明确指出“首页星星突兀、没有功能和交互”，要求把全小程序类似问题找出。本清单直接回应这一要求。关联[总方案](../superpowers/specs/2026-10-07-ui-ux-redesign-design.md)、[全页矩阵](2026-10-07-full-page-experience-matrix.md)。

## 1. 核查范围与证据边界

检查 `app.json` 的 27 个路由，以及 `pages/`、`components/`、`templates/` 下全部 44 个 WXML；清点 52 处图标/图片/插画引用，核对 36 个图标语义名和全局样式中 26 类旧图标伪元素。

52 处是**源码出现次数**，其中 11 处在独立活动页面、5 处在 V4 共用模板、9 处在公共组件、27 处在旧版兼容分支；循环、动态菜单会产生更多运行实例。不能理解为“52 个缺陷”，也不能把旧分支的装饰声称为当前 V4 首屏内容。

机器可复核的路径、行号、引用、事件绑定和源码 SHA256 见[源文件清单](2026-10-07-ui-source-inventory.json)。本轮没有原生截图和真机交互证据，空间上的突兀程度仍需后续原生走查。

判定次序：

1. **提供信息**：菜图、头像、日期状态、错误语义，可保留，即使不可点击。
2. **帮助操作**：返回、关闭、搜索、收藏、清单导航，保留并统一。
3. **有限品牌表达**：首次空态可有小插画，不重复抢主任务空间。
4. **没有明确作用**：标题星星、重复无含义符号、同义入口、空泛占位，删除或合并；不硬造功能保留装饰。

## 4. 没有突兀装饰的页面，不为“全覆盖”添加图形

已检查日志、餐次详情、回顾、同步、偏好、筛选、资料编辑、私房菜、采购预览、做饭、助手历史及六个管理页。多个页面本来就没有正式图标或插画引用。它们的优化重点是主次动作、密度、文本分组、状态与可发现入口，不是补齐一套装饰。

管理页保持目标用户/菜品、权限和危险动作可见；回顾保留真实数据图形；头像和菜品封面是信息内容；日期标识与购物三态是业务状态，均不因为“不可点”而删除。

## 5. 执行与验收方法

每项设计实施后补充：修改路径、页面和状态、保留的事件、前后截图、对应验收项、结果。首先验证 D01/02/04/05/09/11/19/22，它们直接影响用户看到的成熟感。

对每个可见元素回答三问：它表达什么；去掉会损失什么；如果能点，点击会发生什么。答不出来的常态元素默认移除。静态的真实内容和必要状态不用强加交互。

完成标准：27 页及弹层没有无意义的星星/符号/重复插画；可点与不可点能分辨；保留的图标在真实尺寸可识别；图文仍可读；功能入口与状态反馈全部存在。最终由原生页面逐项确认，不能用源码数量或“更简洁”一句话代替验收。
