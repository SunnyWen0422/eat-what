# Agent 操作经验与运行手册

整理日期：2026-10-18。适用于 GitHub、服务器、数据库、构建与上线任务。本文是经验提炼，不是生产状态检查结果或发布授权；具体目标沿用当前用户授权，历史记录不能自行扩大授权。首先阅读 [接手指南](../agent-handoff.md)。

## 1. GitHub 提交推送与仓库整理

### 提交前

1. 确认正式仓库、当前分支、HEAD、origin 和用户目标；区分自己的改动、此前未提交成果及其他任务改动，不直接 `git add .` 混合提交。
2. 查看最终差异、相关验证和文件清单。不得上传私有 `.env`、数据库、日志、运行目录、模型账本、JAR 或凭据；`.gitignore` 不会自动移除已被跟踪的敏感文件。
3. 用明确路径暂存，核对 staged diff，再提交有具体问题和行为描述的提交。提交、推送、部署分别汇报。

### 连接与推送

- 首次连接前检查进程/Git 代理；没有设置时读取 Windows 当前用户启用的系统代理。只输出脱敏的状态，不打印含密码的 URL。
- 对当前 Git 命令使用 `-c http.proxy=...`，不改系统或全局配置，不关 TLS。端口按实际启用值，不复制历史示例。
- 网络错误同一原因至多安全重试一次；有新证据再改变办法。不要盲换 HTTP/TLS/SSH、多次弹凭据窗口。
- 网络已通但出现 `0xC0000022`、`NtCreateDirectoryObject`、MSYS `waitpid` 或 prompt script 失败，先判断执行环境/凭据助手限制。`gh auth token` 读不到 token 不等于普通终端登录失效。
- 已授权且可读取的 GitHub 凭据可以使用，但不输出、不写进命令日志或 Git 配置；不扫描无关凭据，不尝试服务器 SSH 私钥登录 GitHub。
- 若环境确实无法运行凭据助手，给用户一条目标已核对的普通 PowerShell 推送命令；当前就在目标分支时用明确分支名，避免手输 `HEAD:refs/heads/...` 丢失冒号。收到结果后仍查询远端确认。
- 成功标准：远端目标分支完整 SHA 与预期提交一致。退出码、用户说“已推送”、本地 tracking ref 都不能单独代替远端确认。若他人同时推进远端，确认本提交已包含并如实说明，不能强推回退。

### PR、合并与删分支

- 用户给出 PR 或 SHA 时，核对仓库、head/base、完整 SHA、差异、提交关系、评审和 CI 状态。草稿 PR 不等于有问题，也不等于已验收；CI 未运行必须明确。
- 在保全已有改动的前提下本地整合，检查与现有产品决策冲突，运行影响范围内的验证。不能只看“无文本冲突”就认为没有行为冲突。
- PR 描述写问题、结果、实际验证与限制；多行正文使用结构化参数或正文文件，不靠易误转义的 shell 拼接。创建 PR 后按工具要求关联到任务；没有发布指令不顺带部署。
- 删除修复分支须有用户授权，并核实无独有成果、对应修复已进入目标、没有未合并 PR 或其他工作区依赖。普通 merge 可查祖先关系；squash/cherry-pick 要比对补丁与 PR 记录，不能仅凭分支名或提交 SHA 不同判断。
- 先列具体可删对象，再执行已授权范围内的删除；不强删本地有成果的分支，不批量删除未知分支，不清理他人 worktree。

## 2. 服务器访问与故障定位

### 访问入口

历史上使用过 SSH 与阿里云云助手；云助手能在服务器内部查询数据库，SSH 私钥不可用不代表数据库不可用。只使用既有、明确授权的账号和凭据所在位置。核对 CLI 当前版本及帮助、实例 ID、区域和实际命令目标后再调用，不直接执行聊天里复制的远程安装脚本。

旧资料记载过不同 SSH 端口和宝塔入口；不能将它们当作永久配置。当前入口应从可信私有运行记录及已授权的只读服务器/云状态核对。宝塔面板端口、SSH 端口、Java 端口、MySQL 端口不是一回事。

云命令要记录命令/调用 ID、执行状态、退出码和脱敏输出。“已提交命令”不是“执行成功”；结果暂不可读时先查原调用，不重发可能已执行的变更。云助手 `ClientNotRunning` 是代理执行问题，不是 SQL 失败；TCP 接通也不等于协议握手和认证成功。

历史运维脚本及回执可能保存在仓库外任务 `work/` 的对应操作目录。先从带日期的部署报告定位具体目录，再仅检查所需文件；不要全盘扫描密钥或依赖目录。它们不是可无条件重复运行的正式发布工具。

### 分层排查顺序

1. **客户端实际目标：** 项目目录、API 地址、登录身份、请求路径与请求时间。
2. **公网/反代：** 网络、HTTPS、Nginx 路由及状态码。404 优先核对路径和部署版本，不直接修改数据库密码；401/403 优先核对认证及内部令牌。
3. **应用进程：** 服务管理器、PID、cwd、监听、完整运行包和配置来源；服务器本机接口与公网行为是否一致。
4. **数据库：** 在服务器内使用应用配置核对连接、所选库、结构和必要汇总；不要把缺表、缺迁移或无候选当作网络断开。
5. **推荐/模型：** Python 健康、Java/Python 协议能力及内部认证、索引路径，再核对已授权模型请求。健康检查不会证明真实供应商可用。

只读诊断不顺带开放公网 MySQL、修改安全组、重置密码或重启整台服务器。对不明确的失败保留证据，先定位到层再处理。

### 小规格主机内存与生产验收

- 分开核对云侧标称内存、系统可用总量、进程 RSS/PSS、Java 已用/提交/最大堆、数据库缓存及连接上限；不能把最大堆当作整个 Java 进程占用，也不能把虚拟地址保留量当作物理内存。
- 同看 OOM 日志、Swap 读写、内存阻塞和请求耗时。冷页换出后 RSS 降低不等于进程分配永久减少，可用内存增加也不代表机器扩容；一次健康检查不代替稳定性验证。
- 生产验证采用有资源门槛的串行小批，成功结果逐项持久化。触及门槛先停止新请求、核对原回执和资源；不得清轮换、降门槛或重发已完成操作来凑通过数。恢复专属测试快照前核对账号不存在、身份与文件哈希，保持原模型预算，不覆盖既有用户。
- 内存配置变更仍需当前授权、配置备份与验证、必要的维护入口、正常重启和实际运行值回查；不要关闭安全组件或重新回灌业务库。2026-10-22 的[排查与调整记录](2026-10-22-memory-optimization.md)仅作证据索引，里面的参数和门槛不能未经评估照搬到新机器。

### 历史拓扑（仅定位线索，执行前复核）

2026-10-10 的[整版部署记录](2026-10-10-production-release.md)记载：Java 由宝塔的 `spring_eatwhat-backend-1.service` 管理，目录 `/www/wwwroot/backend`；Python 为 `eatwhat-recommend.service`，目录 `/www/wwwroot/recommend-service`；网页在 `/www/wwwroot/eatwhat-web/current`；所有 `/api/` 经 Java 认证及转发。旧“聊天直接绕过 Java”架构图不应覆盖该记录，更不能替代当前 Nginx 检查。

## 3. 数据库访问、提升质量与迁移

- 前端通过应用 API 获取数据，不把 MySQL 用户、密码写进浏览器或小程序。网页开发代理只代理既定公开 GET，不因此开放私人接口或写入。
- “本地程序连接线上数据”仍有生产影响。读分析优先服务器内只读事务/只读账号、限定字段和数量；检查 SQL 是否只读，不调用未知过程，不把原始用户信息输出到聊天。
- 区分三个对象：线上原库、本地原始备份、本地匿名化/治理后的副本。重要原件保留，数据清洗先检查字段、缺失、重复和异常，输出新产物、脚本、审计；不得整库替换生产。
- 迁移前采集当前列、索引、唯一键、外键、字符集/排序规则和实际迁移记录。相同 `V4` 编号曾代表不同历史迁移，不能按文件序号重放新版 SQL。
- `scripts/prepare_legacy_v4_release.py` 基于显式结构快照准备增量，输出到新目录；`scripts/rehearse_legacy_bridge.py` 用于隔离重演。先检查其当前参数与目标，准备文件不等于已经执行迁移。
- 新表和文本列需匹配实际旧库的排序规则，同时保留有意使用 ASCII/二进制比较的幂等键。不要为消除比较错误批量改变全库编码。
- MySQL DDL 不保证整份事务回滚。记录分步回执、已存在对象与形态，部分失败后核对实际结构再续跑，不重复执行含删除/覆盖语义的旧初始化 SQL。
- 备份校验包含文件可读、哈希、压缩完整性和隔离恢复；“导出命令成功”不等于可以恢复。核对前后数量、关系和关键原字段，限制测试数据影响。
- 检索索引是可重建副本。使用明确配置的只读源和新的私有输出路径重建，核对 Python 实际读取的 `DISH_META_PATH` / `INGREDIENT_MAP_PATH`；不能用索引替换数据库或泄漏私人菜谱。

以上涉及生产读取、迁移或写入的步骤仍需当前授权覆盖。详细依据：[访问诊断](2026-10-10-online-access-recovery.md)、[旧库切换要求](../release/local-maturity-cutover.md)。

## 4. 服务更新与发版

### 先辨认更新对象

| 用户目标 | 实际对象与验证 |
| --- | --- |
| 只推送代码 | GitHub 分支；不改变服务器或用户端 |
| 只刷新服务 | 核对现有包与配置，按已验证管理入口重启；不谎称更新到新源码 |
| 更新 Java | 完整 JAR、外部配置兼容、必要数据库增量及实际运行哈希 |
| 更新模型/推荐能力 | Python 源码、依赖、提示词/策略、索引及 Java 协议；不只换一个 Python 文件 |
| 更新网页 | 独立静态构建、资源版本/路径、同源 API 与缓存；开发代理不进入正式静态包 |
| 更新小程序 | 编译/上传开发版、提审、审核、正式发布分别记录；重启服务器不会发布小程序 |

用户原来的“替换 JAR 后重启”适合只改兼容 Java 逻辑的版本。若同时涉及 Python、结构、协议或静态资源，必须按实际差异准备匹配组件，不能承诺只换 JAR 就全功能正常。

### 执行顺序

1. 固定范围、最终源码与相关检查证据，列 Java/Python/网页/小程序/迁移/配置的实际差异。不从旧 target 目录随手拿包。
2. 准备同源候选及哈希，检查包内不含本机/生产秘密；使用服务器原外部配置，不用 `.example` 覆盖真实微信、数据库、Token 和模型配置。配置名和内部令牌沿用既有契约。
3. 经授权核对目标实例、服务管理方式、监听、磁盘、运行包、配置来源、网页指针和数据库结构；确认旧客户端与混合版本兼容策略。
4. 备份当前数据库、运行文件、私密配置、反代/服务定义、适用的会话 SQLite 一致快照；准备经验证的恢复点和维护窗口。不要只备份 JAR。
5. 使用已核实的维护/停写入口，等待或安全处理已受理任务；按隔离演练顺序执行必要增量并替换完整产物。不用旧 `backend/deploy.sh`，不热补 class，不靠杀进程盲等宝塔重启，不启动第二套常驻 JVM。
6. 按依赖顺序启动与核验。确认进程、工作目录、监听和运行哈希；检查健康、能力协商、内部认证和真实路由，网页资源要验证 Nginx 工作用户能读、缺失资源正确返回 404。
7. 对已授权测试账号/数据执行必要业务验收，核对持久结果及不重复写入。仅匿名接口返回 401 或健康 UP 不能宣布全功能通过。
8. 门槛满足再恢复访问；记录部署 SHA、产物哈希、时间、服务、备份、脱敏验收及剩余缺口。未更新的小程序或网页明确列出。

### 回退经验

优先停止新增写入口并保全当前状态，再恢复兼容的运行文件、配置和网页指针；先健康再恢复流量。数据库新增结构不因回退 JAR 自动消失，旧版本未必理解新增实吃、软删除和回执。

恢复流量后已经产生的合法写入必须保留。不得直接回灌上线前整库备份“撤销升级”；先备份当前状态、核对兼容并按已演练方案处理增量。无法证明无损时如实说明，不宣称一键无损回滚。

历史依据：[整版部署与失败恢复](2026-10-10-production-release.md)、[仅重启核对](2026-10-11-backend-refresh.md)、[完整 JAR 更新](2026-10-11-edited-copy-backend-update.md)。`SERVER.md` 仅作历史定位，不直接照抄旧命令。

## 5. 本机配置与真实模型测试

私有配置、账本和运行目录按既有受控位置读取，仅提取必要字段，不打印内容。测试入口先核对数据库/API/账号/供应商来源；命令含 `local` 或 `Offline` 不能证明没有线上调用。

仓库中的 `backend/src/main/resources/application.yml.example`、`recommend-service/.env.example` 说明配置字段，不是生产配置。实际配置路径由当前运行命令/服务定义和私有记录确定；用定向解析核对字段是否存在或两端是否一致，不把整份配置打印到工具输出。源码已有凭据线索也不能当成授权扫描整个系统凭据库。

`scripts/run_maturity_live.py` 要求隔离配置、全新输出目录、明确真实调用参数和匹配授权的预算账本。每次 HTTP 尝试先预留额度，失败也计入；取消不意味着供应商停止计算或退还费用。不要换账本绕过限额，也不要把正式服务配置为替身来避免测试花费。

新包未被本地运行器显式选中时，打包成功不会自动更新测试服务；固定快照、端口、进程归属和哈希必须一起核对。无法看到普通终端进程时保留环境限制，不放宽归属验证。

## 6. 操作交接最小清单

```text
目标与授权范围：只读 / 本地 / GitHub / 指定生产变更
来源：分支、完整源码 SHA、未提交差异、产物哈希
目标核对：实例/服务/数据库身份与归属；不写凭据
前置保护：有效备份、维护、兼容、模型预算（按需）
实际执行：命令/调用标识、开始结束时间、退出状态、脱敏结果
最终事实：远端 SHA / 运行哈希 / 结构 / 网页版本 / 微信发布阶段
未执行与剩余问题：明确列出，不把健康检查当全功能验收
恢复与后续：安全恢复点、私有证据定位、下一项具体行动
```

本手册应随已确认的操作经验更新，但不将本机代理、当前端口、密码或整份原始回执复制进 Git。没有现场核对时使用“历史记录”“待确认”，不要把上一次的状态描述成现在。
