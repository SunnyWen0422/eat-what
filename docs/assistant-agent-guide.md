# 菜品推荐 Agent 说明文档

> 早期简版说明。v2 模型驱动 Runtime 已落地，当前以 `docs/assistant/agent.md`、`docs/assistant/spec.md` 和技术手册为准。

## 1. 文档目的

本文档说明菜品推荐 Agent 的定位、运行边界、调用流程和维护方式，供前端、后端、数据和运维人员共同使用。

## 2. Agent 定位

Agent 的目标是帮助用户完成“一顿饭或一段时间的用餐安排”。它负责理解自然语言、调用受控的菜品检索能力、生成可调整的方案，并将用户确认后的方案交给业务接口保存。

Agent 不直接操作数据库，不替用户默认保存日历或购物清单，也不把一次性表达自动记录为长期偏好。

## 3. 支持的任务

- 安排一餐：根据人数、餐次、口味、忌口和时间生成组合。
- 利用现有食材：识别食材别名，优先推荐能使用的菜品，同时说明仍需购买的主要食材。
- 周期安排：模型可按日期和餐次规划多日计划；当前版本先完成单餐闭环，周期任务的分段续作仍在后续迭代。
- 局部换菜：只替换用户指定的菜，保留其余条件和菜品。
- 做法解释：基于真实菜品数据解释步骤、器具和操作负担；缺失信息必须标为未知或估计。

## 4. 推荐处理流程

1. 立即回显用户输入，建立或恢复当前用户会话。
2. Runtime 将全局规则和工具 Schema 交给模型，由模型判断需要的查询和变换步骤。
3. 服务端只执行白名单工具；通过别名检索、结构化筛选和 BM25 召回真实候选。
4. 先执行忌口、过敏和明确排除等硬约束，再按收藏、近期记录、偏好、食材匹配和操作负担排序。
5. 进行整餐检查，避免主料重复、做法过度单一或组合不合理。
6. 程序校验模型 JSON、菜品来源、日期、人数和动作权限后返回主方案、替代方案和理由。
7. 保存日历或生成购物清单前，必须先预览并等待用户确认；模型不能调用写入工具。

## 5. 工具与数据边界

Agent 只能调用白名单工具，例如菜品检索、菜品详情、用户上下文读取、方案预览和操作确认。工具参数必须是结构化数据，禁止拼接或执行任意 SQL、脚本和文件操作。

菜品 ID、食材用量和用户权限以服务端返回为准。辅助索引只用于召回，写入前必须回主数据库复核菜品仍存在且用户有权限。

## 6. 偏好与记忆规则

- 当前任务条件只在当前任务内生效。
- “今天不想吃鱼”属于临时条件，不自动升级为长期禁忌。
- 收藏、近期日历记录和用户明确保存的偏好可参与排序。
- 新增长期偏好前必须明确提示并取得用户确认。
- 会话、消息和草稿按用户隔离；游客使用短期会话。

## 7. 写入安全

所有写入操作都必须绑定已确认的方案版本和幂等标识。日历存在同日期同餐次记录时，默认返回冲突预览并保留原记录，不静默覆盖。购物清单继续按菜展示食材，并保留汇总结果。

## 8. 模型使用原则

DeepSeek 是可选的规划模型：它可以动态分析意图、连续调用查询/变换工具、组合方案、换菜和换算份量，但不能绕过程序约束。模型输出的菜名必须映射到真实菜品 ID；模型生成的新菜只能作为带来源标识的草稿，用户确认后才能保存。

模型不可用、超时或返回格式错误时，系统应保留已生成内容，提示用户重试或转入普通选菜流程，不显示无限加载状态。

## 9. 配置与部署

生产环境通过服务器环境变量配置：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。密钥不得提交到仓库。菜品数据更新后应重新构建辅助索引，并执行索引审计和回归测试。

## 10. 验收重点

重点验证否定与改口、多轮指代、局部换菜、多日计划、无匹配、索引过期、重复提交、用户隔离、日历冲突、模型超时、断网、键盘弹出和四种手机尺寸。评价指标应优先关注完成一餐的时间、追问次数、方案采纳率和换菜后的满意度。

## 11. 技术架构

请求链路为：微信小程序 `pages/chat` → `utils/api.js` → Java `AssistantController` → Python 推荐服务 `/assistant/**` → DeepSeek（可选）与 MySQL 只读查询、SQLite 会话侧库。Java 层负责认证、限流、跨服务转发和统一错误；Python Runtime 负责模型工具循环、任务状态、严格校验和降级；确认后的日历/清单动作由 Java `AssistantActionService` 执行。

会话包含 `session_id`、用户标识、消息列表、当前方案版本和创建/更新时间。每次修改生成新版本，换菜和撤销不会修改历史版本。请求带上用户身份和会话 ID，服务端再次校验归属，不能只相信前端传入的用户 ID。

## 12. 主要接口约定

| 接口 | 用途 | 是否写入业务数据 |
|---|---|---|
| `POST /assistant/sessions` | 创建会话 | 仅写会话侧库 |
| `GET /assistant/sessions/{id}` | 恢复会话和方案 | 否 |
| `POST /assistant/sessions/{id}/messages` | 解析问题并生成回复 | 写消息和方案草稿 |
| `POST /assistant/sessions/{id}/actions/preview` | 预览保存日历/清单 | 否 |
| `POST /assistant/sessions/{id}/actions/confirm` | 确认预览并执行操作 | 通过受控业务服务 |
| `GET /assistant/tasks/{id}` | 查询任务状态和结果 | 否 |
| `GET /assistant/tasks/{id}/events` | 查询阶段进度 | 否 |
| `POST /assistant/tasks/{id}/cancel` | 请求停止任务 | 仅更新任务状态 |
| `DELETE /assistant/sessions/{id}` | 删除会话 | 删除会话侧数据 |
| `GET /assistant/tools` | 查看技能版本和能力 | 否 |

消息响应包含 `task_id`、`task`、`mode`、`reply`、`plan`、`actions`、`events` 等字段。前端只使用结构化菜品 ID，不从自然语言中猜测菜名。任务状态区分 `queued`、`understanding`、`querying`、`planning`、`validating`、`awaiting_confirmation`、`completed`、`failed`、`cancelled`。

## 13. Agent 技能契约

技能定义位于 `recommend-service/assistant_skills.py`，当前版本包含 `meal_plan`、`ingredient_match`、`period_plan`、`replace_dish`、`howto`。每个技能声明必需输入、允许调用的工具、硬约束、追问条件和输出字段。增加技能时必须同步版本号和 `/assistant/tools` 清单，禁止在提示词中隐式增加未审计能力。

## 14. 本地配置步骤

1. 复制 `recommend-service/.env.example` 为 `.env`。
2. 设置 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL`。
3. 设置 MySQL 只读账号及数据库连接参数。
4. 执行 `python scripts/build_assistant_index.py` 构建索引。
5. 执行 `python scripts/audit_assistant_index.py` 检查字段、别名和来源。
6. 启动 Python 推荐服务，再启动 Java 后端和微信开发者工具。

## 15. 关于 API Key

目前仓库只有占位配置 `DEEPSEEK_API_KEY=your_deepseek_api_key_here`，没有发现实际 Key。助手在没有 Key 时仍能使用本地确定性解析、检索和推荐；模型规划层不可用时会明确标记 `mode=rule`，不会导致核心选菜流程失效。

请不要把 Key 发在聊天、提交记录或 `.env` 文件中。应直接在服务器环境变量或密钥管理服务中设置，例如：

```powershell
$env:DEEPSEEK_API_KEY = "你的真实密钥"
```

配置后重启 Python 服务，并用一次普通助手请求确认日志中显示模型调用成功；日志只能记录成功/失败和耗时，不能记录完整密钥或用户原始隐私内容。

## 16. 用户使用说明

进入底部“助手”，可选择“安排一餐”“用现有食材搭配”或“安排几天”，也可以直接输入自然语言。示例：

- “今晚两个人，清淡一点，30 分钟内能做好。”
- “我有番茄和鸡蛋，但不要每道菜都用番茄。”
- “汤保留，肉菜换一道，不要再炒了。”
- “安排下周三个工作日晚饭，尽量别重复主料。”

看到方案后可保留某道菜、换菜、查看做法或撤销。点击“保存日历”或“加入清单”时先查看预览，再确认执行；如果日历已有记录，系统会展示差异并默认保留旧记录。

## 17. 故障排查

- 回复很快但没有模型润色：检查 Key、网络和模型名；核心推荐仍可正常使用。
- 一直显示处理中：前端 30 秒超时后应出现重试按钮；检查 Python 服务健康状态和网关日志。
- 找不到菜品：运行索引审计，确认菜品已发布且索引更新时间正常。
- 保存提示冲突：这是保护机制，查看差异后选择保留原记录或返回修改，不要重复点击确认。
- 用户看到其他人的历史：立即停用相关接口并检查会话归属校验、认证拦截器和会话侧库数据；这是高优先级安全问题。
