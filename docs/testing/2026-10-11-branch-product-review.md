## 已修正

| 问题 | 当前结果 | 关键保护 |
| --- | --- | --- |
| 复制后取消编辑仍留下副本 | 先编辑草稿，保存时一次事务创建最终副本 | 取消零写入、原菜谱保留、版本校验、丰富字段与来源保留、未知结果重试同一请求 |
| 新编辑保存被旧后端误当普通复制 | 使用独立 `/api/dishes/{id}/copy-edited` | 旧后端 404 时保留输入，不回退旧复制或假报成功；旧待确认复制继续原路由恢复 |
| 个人编辑把配餐误当荤菜 | 新增、编辑、复制与个人筛选保留 `side/配餐` | 分类不静默改变 |
| 结构化配方直接显示 JSON | 用料和步骤显示可读行 | 未编辑的字段仍回传原 JSON；未知量不猜测 |
| 预加载遗漏封面 | lite 查询补 `IMAGE AS image`，图片保留至内存/持久缓存/旧离线推荐 | 查询上限、公开过滤和参数化不变；正常 V4 原本用完整字段，不把此修复夸大为全 V4 根因 |
| 临时断网清除登录 | 仅明确 401/403 且账号、环境、登录代次均未变时失效 | 网络/500/503 保留登录，迟到校验不影响新账号；失效时同步清理全局状态 |
| 控件全宽被公共样式覆盖 | 我的、历史、日历、单餐、购物、偏好共 8 处修正 | 原事件、确认、禁用与恢复仍保留；偏好保存行高随字号变化 |
| 原始异常或开发口径出现在页面 | 页面和 API 弹窗共用安全文案，删研究说明、版本/指纹、普通用户诊断入口 | 具体字段校验、冲突、真实失败、安排变化和保存结果待确认仍给出恢复动作 |
| 数量面板及其他页面信息重复 | 数量面板仅留数量控件与“应用后保留这份搭配配置”；设置、日历、帮助、采购减少重复说明 | 目标只在需要处出现；多餐/人数不同保留来源差异；真实数量不可靠仍能核对 |

复制预览的旧“确认就创建”说明已删除。详情不再用重复副标题解释页面名称，也不常驻空营养提示；份数和用量核对仍保留。偏好状态为空时不再出现孤立的绿色圆点。
