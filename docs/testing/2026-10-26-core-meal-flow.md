# 当前餐次保存：第一轮体验改造与验收

日期：2026-10-26。范围为[体验优化方案](../superpowers/specs/2026-10-26-user-experience-direction-design.md)的阶段 0 本地补验与阶段 1“生成一餐 → 保存记录”。保留现有视觉风格，不扩展到新的推荐算法、营养标准或全页面重设计。

源码基线：`codex/v4-meal-workspace-green-20261003`，HEAD 为 `2ee6397a5d86f05637bec80ec077212a0e7789b2`，叠加此前已记录的未提交体验修复及本轮改动。此前修复见[产品体验复审](2026-10-26-product-experience-review.md)。本轮没有提交、推送、发布小程序或更新线上服务。

## 用户能感知的变化

| 场景 | 本轮行为 |
| --- | --- |
| 当前餐次为空，已生成菜单 | 点击“保存到日历”直接保存。正常路径从“生成、保存、面板再保存”减少为“生成、保存”两个主操作。 |
| 当前餐次已有记录 | 面板显示原菜单、新菜单和目标餐次；一次“确认替换”提交，取消不写入。版本变化仍拒绝覆盖。 |
| 希望放在其他日期或餐次 | 在餐单操作中选择“保存到其他餐次”，再选择日期与餐次；原来有另存提示的位置也使用这一入口。 |
| 请求仍在处理或结果未知 | 保留菜单，主操作显示“继续完成保存”。直接保存不会突然变成选择餐次面板。 |
| 已保存成功但响应丢失 | 查询对应保存回执，恢复已保存状态；确认成功后不重放写入。 |
| 保存被明确拒绝 | 保留当前菜单及具体拒绝原因，提供“重新读取这餐”；不会误导用户重新生成。 |
| 返回页面、切账号或进入新一天 | 延续账号/餐次隔离。首页新一天展示当天，旧日期的草稿和未完成保存仍归原日期，可显式打开恢复。 |

一次保存仍产生一条餐次记录；未来菜单到对应日期才计入默认回顾。采购状态不作为另一种用餐记录。未改变这些口径。

## 实现与边界

- 共用页面的 `onConfirmPlan()` 对无记录的当前餐次冻结菜单并直接调用原保存链；`onOpenSaveTarget()` 专门打开日期/餐次选择面板。
- 覆盖确认沿用冻结菜单、账号身份、忙碌状态、来源版本、目标记录版本及目标读取竞争保护，移除第二次相同的确认按钮点击。
- `presentation` 只存于本地待完成操作中，不加入 HTTP 请求体，也不更改请求身份。旧本地日志缺少此字段时继续用原面板恢复。
- 菜谱选菜的 `save=1` 跳转保持先选择保存目标，页面初始化不自动写入。直接保存、打开目标面板和最终提交前重新核对同餐次恢复日志，避免从次级入口绕过助手待处理状态；仅在明确需要恢复时返回对应入口。
- 结果未知时仍按原请求查询或恢复；明确 4xx 拒绝解除未知请求状态，但保留菜单与原因；409 必须先读取最新记录后再次确认。
- 本轮审查发现并修复：明确拒绝原来会退回“生成菜单”；新增恢复状态又曾遮住具体拒绝原因。两者均先以真实页面/存储夹具复现，再修复。独立复核还发现次级保存入口绕过助手未完成操作，以及菜谱页保存跳转的副作用，均补回归后修复。
- 未增加数据库表、迁移版本或后端接口字段。数据库检查只在新建的本地临时实例上运行现有统一记录迁移，使用合成数据。

## 验证结果

| 检查 | 结果与范围 |
| --- | --- |
| 主流程及保存目标回归 | 9 份文件，最终 171 / 171 通过；覆盖直接保存、明确覆盖、取消、拒绝原因、409、未知恢复、原请求身份、重复点击、目标读取竞争及日期边界。同餐助手待恢复/处理中/待确认时，打开目标面板前后都不能绕过保护写入；其他餐次不受误阻。 |
| 受影响入口及状态回归 | 最终 12 份文件，90 / 90 通过；与上行文件不重叠，合计 21 份、261 / 261。另一次包含验收工具的 121 项批次中，120 项首次通过，1 项临时目录链接检查因本机权限失败，取得对应本地权限后单项通过；这个批次与前述回归重叠，不重复累计。 |
| 迟到响应保护 | 包含于主流程最终批次：成功/失败回执分别覆盖切换账号、进入另一餐次和页面卸载。旧回执不覆盖当前界面或另一账号记录。 |
| 本地真实 MySQL | 全新隔离实例：统一记录迁移、中断后的继续执行、再次执行、账号/日期读取、未来日期边界、收藏与购物数据保留通过。真实 Java mapper 输出 JSON 后再通过生产 Python schema 验证。 |
| 静态检查 | 233 份源代码/配置语法检查、51 份模板注册/处理器引用、24 份普通页面/弹层文案检查及资源/密度令牌检查通过。末次修改的源文件及模板另行核对，最终交互由定向回归覆盖。 |
| 独立复核 | 发现的三项入口/提示问题已修复，最终独立边界回归 11 / 11 通过；复核范围内无未解决阻塞。 |
| 后端构建 | 本轮没有改后端源码；此前已验证的构建证据复用，不重复编译整个服务。隔离数据库检查使用独立测试构建目录。 |

临时数据库首次受回环连接权限限制；增加连接超时与具体失败原因后确认是 `WinError 10013`，允许本地隔离连接后验证通过。数据库检查结束已确认本轮拥有的进程退出。目录链接检查只验证验收工具的路径保护，不操作微信工具或用户界面。

旧验收预期同时按现行规则更新：默认首页跨天进入当天，历史结果页仍可保持显式餐次；原日期未完成请求可单独恢复；已保存页面展示记录快照，因此草稿版本断言从真实工作区读取；购物费用标题使用现行“待买估算”。没有通过移除业务保护换取通过。

- 独立 React 网页、线上服务和生产数据未变更。后续阶段继续按方案推进，本轮不宣称全路线完成。
