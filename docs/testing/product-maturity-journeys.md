# 主流程与恢复状态

T10使用纯展示函数deriveMealJourney统一主按钮及状态优先级：结果未知→版本冲突→正在处理→条件未应用→等待确认/正常下一步。实际用餐只读取原actual.status；已保存计划或全部食材已买均不推断为吃过。保存到别日的查看动作使用原确认回执目标。

collectRecoveryPointers只扫描当前账号/API对应的工作区、实吃、个人内容和助手已有日志。它输出入口引用，不复制请求正文、不持久化新队列，也不在发现待办时发送任何写请求。原请求依然由原工作区/实吃/复制/采购/助手流程核对和重试。

“我的→数据同步”现在汇总这些待核对入口；原历史本机安排仍逐条确认。首页主状态最多选当前餐一个相关恢复项；无法确认来源的待办仅放在恢复页，不猜日期。实吃恢复入口读取指定餐次的原待确认请求后打开编辑框，不自动保存。

保留原有计划、采购、复制和菜单确认函数；未增加另一套领域状态或自动补写规则。个人菜单的入口复用已有菜单恢复/编辑页面，具体权限和已删除来源继续由原接口核对。

验证：75项Node回归通过，覆盖首次安排→别日保存→采购→做法→个人内容复用、跨自然日、取消/恢复、原请求、同名对象、冲突及十次重复确认只有一次边界写调用。该计数是隔离HTTP夹具断言；实际MySQL写入次数、回滚、进程重启证据由T21补充。原生呈现由T23补充。
