基线 `19cb4907cfbfce3251eb981af792d672962d804c`，分支

只调整小程序前端，不改服务契约，不调用生产或真实模型。

- “查看”展示当前菜单，不能展开本餐设置；编辑中的设置不能悄悄丢弃。
- 当前有效菜单同排显示“查看 / 撤销 / 采用”。撤销依据当前版本与实际历史；
  历史菜单不可撤销新版本，五角星仍是收藏。
- 助手已完成的菜单更新同步到共享工作区，返回首页可见；同步失败可继续读取，
  不重发已完成的生成请求，不从聊天卡片伪造工作区。
- “采用”保存卡片对应的当前菜单到其日期、餐次；存在不同日历安排先确认替换。
  保存后显示“已采用”，保留日历刷新及服务端回执检查。

## 状态边界

| 状态 | 处理 |
| --- | --- |
| 正常完成 | 读取最新工作区，按真实版本启用操作；日历保存验证原回执 |
| 同步失败 / 读取仍旧 | 保留同步目标，显示继续查看结果入口；只重读，不重新生成 |
| 重复点击 | 操作期间锁定，保存成功不重复写入 |
| 取消替换 | 不保存，保留菜单和输入 |
| 保存结果未知 | 使用持久化原请求恢复，禁用新的采用或撤销 |
| 版本冲突 / 历史卡片 | 禁止旧卡片修改新菜单，可查看当前菜单 |
| 账号、服务、餐次切换 | 晚到结果无权更新或保存新上下文 |
| 部分完成 / 后续任务待确认 | 展示已有菜单，保留任务恢复，阻止竞争写入 |

## 验证

已复现三个具体缺口：“查看”同时打开设置；菜单回读失败后已完成请求失去
恢复入口；已完成的旧撤销在新菜单到达后被误当成未知结果。撤销原本还受
最新对话的 active 条件限制，与当前菜单的实际历史不一致。

现在查看使用独立菜单区域，操作资格绑定共享工作区版本和历史；同步失败
持久保存只读目标，继续读取时不重发生成；完成且已被更新版本取代的反馈不
再常驻。未完成的任务或请求不会按“旧提示”隐藏。

“采用”沿用现有工作区确认接口，保存前读取目标，校验来源版本并冻结菜单。
已有日历安排时确认替换；来源变化时读取最新菜单而不保存；已采用状态依据
真实保存回执与当前日历版本，旧卡片不能覆盖新菜单。
