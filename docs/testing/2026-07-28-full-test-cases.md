# EatWhat 全量测试用例文档

**版本：** 1.0

**编写日期：** 2026-07-28

**适用分支：** `codex/main-integration-20260726`

**测试对象：** EatWhat 微信小程序、Spring Boot 后端、FastAPI 推荐服务、MySQL 数据与离线脚本
**测试原则：** 先验证用户可见反馈，再验证数据正确性，最后验证跨服务一致性；所有写入测试只允许使用隔离测试库，不连接生产库。

## 1. 测试目标

本轮测试覆盖以下目标：

1. 验证小程序 20 个注册页面的加载、交互、导航、空状态、错误反馈和弱网行为。
2. 验证菜品浏览、菜系/标签筛选、推荐筛选、偏好设置和推荐结果的业务规则。
3. 验证食谱记录、收藏、日历、统计、聊天和管理功能的数据隔离与权限边界。
4. 验证购物清单按菜品分组保存、人数换算、食材解析、采购汇总、增删查改、离线队列和版本冲突。
5. 验证 Java API、FastAPI 推荐服务、MySQL schema、数据回填和导入脚本的契约一致性。
6. 形成可复现的测试证据：测试命令输出、HTTP 请求/响应、SQL 查询结果、页面截图和缺陷日志。

## 3. 测试环境与数据

### 3.1 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11，PowerShell 5+ |
| 前端运行时 | Node.js，可执行 `node` 和 `npm.cmd` |
| Java | JDK 8 兼容项目，推荐 Java 21 + Lombok 1.18.32 |
| Java 构建 | Maven，可访问 Spring Boot 2.7.14 依赖或已准备离线仓库 |
| Python | `.test-venv\Scripts\python.exe`，或 `CODEX_PYTHON` 指定解释器 |
| 数据库 | MySQL 8.0，测试端口默认 `3307`，只使用临时数据目录 |
| 小程序 | 微信开发者工具，导入仓库根目录 |
| 服务地址 | Java 本地 API `http://127.0.0.1:8080/api`；Python `http://127.0.0.1:8000` |

### 3.2 固定测试账号

| 标识 | 用途 | 约束 |
|---|---|---|
| 用户 A | 普通用户主流程 | `userId=1001`，只能访问自己的记录、收藏、自定义菜品和购物清单 |
| 用户 B | 隔离与越权验证 | `userId=1002`，不能读取或修改用户 A 的资源 |
| 管理员 | 管理模块 | 使用本地配置中的管理员 ID，不使用生产账号 |
| 未登录访客 | 鉴权与降级 | 无 Token 或过期 Token |

### 3.3 固定业务数据

1. 标准菜品：`炸猪排`、`葱烧大排`，两道菜均含结构化食材 `猪排`，用于验证“主视图按菜分开、采购汇总可合并”。
2. 数量样本：精确值 `345克`、范围 `2-3升`、分数 `1/2茶匙`、定性值 `适量`、未知单位。
3. 人数样本：基准 `2名成年人总量+15%冗余`，目标人数 `1`、`4`、`50`，非法值 `0`、`51`。
4. 筛选样本：菜系 `SICHUAN`、`CANTONESE`，标签 `HOME_STYLE`、`FRY`，烹饪时间 `30` 分钟。
5. 记录样本：同一天早餐、午餐、晚餐各一条；至少一条自定义菜谱和一条系统菜谱。

## 4. 测试用例约定

### 4.1 优先级

- **P0**：阻断启动、登录、核心推荐、购物清单写入或数据安全的问题。
- **P1**：核心流程可用性、数据正确性、权限、弱网和跨服务一致性问题。
- **P2**：非核心交互、提示文案、视觉细节和低风险兼容性问题。

### 4.2 用例状态

`未执行`、`通过`、`失败`、`阻塞`、`不适用`。每次执行必须记录执行日期、环境、操作者、状态和证据路径。

### 4.3 缺陷证据

缺陷编号格式：`模块-优先级-序号`，例如 `M08-P1-003`。至少保留：

- 页面截图或录屏，包含页面状态和操作入口。
- 请求 URL、方法、脱敏请求体、响应状态码和响应体。
- Java/Python 日志或浏览器控制台日志。
- 测试数据库查询结果、数据快照或回滚记录。
- 复现步骤、实际结果、预期结果和影响范围。

## 8. 通过标准

1. P0 用例全部通过；任何 P0 失败都阻断发布。
2. P1 用例通过率必须为 100%，或有明确批准的已知问题、影响范围和临时规避方案。
3. 前端、Java、Python 自动化测试不得存在未解释失败；环境阻塞必须记录精确错误和复测条件。
4. 隔离 MySQL 测试必须验证导入、外键、唯一约束、用户隔离、回滚和临时目录清理。
5. 购物清单必须满足：主视图按菜独立、汇总只读、15% 不重复计算、用户覆盖不被刷新覆盖、重复 requestId 不重复写入。
6. 弱网测试必须证明页面不会长时间空白或永久 loading，且本地反馈和待同步数量可见。
7. 性能测试必须产出 p50/p95/p99，推荐筛选 p95 目标低于 800ms。
8. 测试结束后只保留可审计报告；临时 MySQL 数据目录、测试账号和生成缓存不得进入 Git。
