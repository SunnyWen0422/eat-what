## 合并时发现并修复的问题

1. 新 npm 直接 Node 测试把 Windows 磁盘路径作为 ESM 地址，实际报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`。改为标准文件 URL；6 项 npm 启动测试通过。
2. 体验页跨日恢复手动拼接旧访客缓存键，与环境隔离后的存储键不一致。真实页面/存储的两个回归分别复现“漏读本环境草稿”和“误读旧无环境缓存”，统一 `getUserStorageKey` 后通过。旧日历测试夹具同时对齐实际键格式。
3. 食材准备页把表达式 `&&` 编码成 `&amp;&amp;`，微信原生 WXML 编译失败。修正表达式后，全部模板编译通过。
4. 原打包器会包含提示词目录内的任意文本草稿。新分支的私有文件排除断言复现该问题，现仅打包明确使用的 `recommendation.txt`；所需策略文件仍完整保留。
5. 新增运行时、打包和助手候选测试使用了旧接口夹具。更新夹具以覆盖当前 JAR/进程检查、交付清单和结果附加证据接口，保留原业务断言；没有删除失败测试或放宽生产校验。

独立只读审阅核对了工作区规则、指定餐次保存、质量复制、购物回执与缓存恢复，提出的跨日访客问题已修复并复核。旧购物回执兼容，新字段空值序列化不改变旧请求哈希。
