# 吃什么独立网页：待验收开发版

这是一份可离线搬运的静态候选。源码已通过 Chrome 开发模式的交互检查，交付候选仍未完成跨浏览器、设备、线上数据或部署验收，不能据此上线。候选不附带菜谱数据、个人备份、账号、令牌或服务端凭据。修复及验证范围见源码中的 `docs/testing/2026-10-10-independent-web-repair.md`。

## 本地打开

1. 解压 ZIP 到新的专用目录，保留所有文件层级。
2. 使用 Node.js 24.x。在解压目录运行：
   `node tools/serve-release.ts . --port 4173`
3. 浏览器打开 `http://127.0.0.1:4173/`，固定导航是 `/#/today`、`/#/recipes`、`/#/calendar`、`/#/my`。不要用 file:// 直接打开 HTML。Ctrl+C 停止。

服务器启动前逐项验证 SHA256SUMS 和 release-manifest.json；修改文件会拒绝启动。此工具只依赖 Node 标准库，不需要 npm install。Windows/macOS/Linux 均可使用上述命令，但跨系统实际运行仍待验收。换一个端口就换了 origin，原端口的个人数据不会自动出现。

本地工具的 /api/ 固定返回 503 JSON，/health 返回 candidate-local-only；/main 和 ACME 返回 404。这些响应刻意说明工具没有接入真实服务。它们只能证明静态路由不会吞掉保留命名空间，不能证明旧服务无回归。

## 能体验什么

- 今天、菜谱、日历、我的四个页面及浏览器本地个人记录
- 自定义菜、收藏、计划和实际记录分离、采购编辑、回顾与备份导入/导出
- 公共菜库不可用的明确状态；本地个人记录仍可打开

正式菜品只通过同源公开 GET API 读取。本候选不把历史整理菜谱或测试数据作为兜底，所以公共菜谱和自动菜单可能不可用。未知原料、份量或质量状态不会被猜成已核验；硬忌口仍需自己核查标签和实际食材，不提供过敏安全保证。

## 数据和搬家

个人数据只在当前浏览器的 IndexedDB；无账号云同步。浏览器/隐私窗口、协议、主机或端口不同都是不同存储空间。导出 JSON 到自己控制的位置，备份包含个人记录，请不要随意转发。正式导入先查看预览和数量，按界面确认整体恢复；损坏/较新 schema 可导出 raw 数据待处理，不要清库碰运气。资源回滚不删除个人数据；较旧应用遇到较新 schema 应保持只读。

SHA256SUMS 能检查是否一致，不是签名或独立内容授权。THIRD-PARTY-LICENSES.txt 收录 react、react-dom、scheduler 的 MIT 许可；PROJECT-NOTICE.txt 说明仓库尚未声明通用项目开源/再分发许可；这不妨碍按用户批准范围交付本次独立分支、草稿PR和Library文件。线上菜谱披露许可仍待确认。nginx-web.example.conf 只是评审示例，不能覆盖现有生产配置。
